# 桌面等位区（"无限屏"）与卡片生命周期统一设计

> 2026-08-13 产品提出三条：①点击后台胶囊进展卡闪退，需要统一的卡片退出/缩小逻辑；
> ②放不下的卡不该直接不显示，应等有空位（如关掉导航腾出的位置）再显示；
> ③考虑"无限屏"——低优先级新卡排在界面之外，有空位再进来。
>
> 判断：三条是同一个升级。②③本质相同（等位再上台）；①的"统一逻辑"由升级后的
> 生命周期表兜住。核心变化一句话：**"放不下"从一种失败变成一种状态。**

## 1. 现状与缺口

今天桌面是定容世界（48 单元）：
- 新卡放不下 → 挤出别人（按 priority/LRU）或整体失败（DESKTOP_FULL 拒绝）
- 被挤出的**任务卡**直接消失（只有横幅告知），空间腾出来也不回来
- 已有的恢复通道（reconcile）只管三件事：规则卡补回、尺寸回落、位置粘性——
  **任务卡没有"等位"资格**，这就是②的缺口
- 进展卡闪退（①）：待查 bug，疑似 render 刷新路径上的某个撤卡分支误伤，
  修复列入 W1（先复现定位，不带猜测上补丁）

## 2. 目标模型：台上 + 等位区

```
┌─ 台上（onstage）────────────────┐   ┌─ 等位区（offstage）──────────┐
│ 48 单元真实栅格，现有仲裁不变     │ ← │ 放不下的卡排队：按 priority   │
│ 挤出 ≠ 消失：降级进等位区 ————→ │   │ 权重（urgency×10+kind）+ FIFO │
└─────────────────────────────────┘   │ 上限 8 张，超限按优先级淘汰    │
        ↑ 空间释放（撤卡/缩卡/导航结束）│ （淘汰才真消失，横幅告知）     │
        └── reconcile 每 tick 依序上台 ┘
```

- **入场**：`show/render` 放不下 → 不再返回失败，返回 `{status:'ok', staged:true}`，
  卡进等位区。调用方（模型/规则）拿到的是"已受理"，不用改任何建卡代码。
- **挤出**：被挤的卡转入等位区（数据全保留），横幅从"我把天气收起来了"升级为
  "天气先收后台了，随时说'看天气'叫回"。
- **上台**：并入现有 reconcile 管线（tick 驱动）——空间够了按优先级依次上台，
  复用位置粘性（prevPos）与家族语义。**上台是恢复不是打扰，静默进行**（既有公理）。
- **等位区里的 ttl**：`untilDismissed` 冻结（内容不过期）；秒数 ttl 继续走
  （问题卡在台下过期一样散——没人看到的问题更该散）；`untilTaskEnd` 照常。
- **用户召回**：语音"看天气" → 模型调 `card.focus`（已有工具），focus 对台下卡
  的语义 = 提升到队首并立即尝试上台（必要时挤别人——用户点名的卡优先级最高）。

## 3. 可见性：无限屏的视觉表达

- 台下有卡时，桌面右缘出现**边缘提示条**（一条竖向浅色 pill，写"⋯ N"）——
  "界面之外还有内容"的最小视觉隐喻，不占栅格。
- 点提示条 → 出**台下清单卡**（复用 list 模板：卡名 + 一句摘要），点某项 =
  召回它（focus 语义，answer 路由合成"看XX"进对话或 desk 直调——用交互声明定）。
- 状态栏不加新芯片——任务芯片管"在干活"，边缘条管"有内容在台下"，职责不混。

## 4. 卡片生命周期统一表（①的"统一逻辑"）

| 通道 | 触发 | 去向 | 已有/新增 |
|---|---|---|---|
| 用户划走 / ✕ | byUser | 消失（规则卡抑制防诈尸） | 已有 |
| 翻篇 | 任务闭环（设目的地等） | 消失 | 已有 |
| ttl 到期 | 秒表/untilTaskEnd | 消失 | 已有 |
| 规则失效 | when 不再成立 | 消失 | 已有 |
| **挤出** | 仲裁 | **→ 等位区**（原：消失） | 本轮改 |
| **放不下** | 入场失败 | **→ 等位区**（原：拒绝） | 本轮改 |
| 压缩 | 仲裁 | 台上缩小（desiredSize 记忆） | 已有 |
| 回落/上台 | 空间释放 | reconcile 静默恢复 | 扩展 |
| 淘汰 | 等位区超限 | 消失 + 横幅 | 新增 |

缩小逻辑维持三级：物理（仲裁）> 意愿（sizeLocked）> 建议（defaultSize），不动。

## 5. 模型视角（必须同步，否则模型重复建卡）

- `desk.summary()` 增台下段："台下还有：成都天气、我的收藏（说'看XX'可叫回）"。
- `desktop.getLayout` 返回 `staged: [...]`。
- 工具返回：staged 上屏时 message 带"桌面满，先排在台下，有空位自动显示"——
  模型好如实转述（"天气查好了，屏幕满了先收着，你说看天气随时调出来"）。

## 6. 边界与判断

- 等位区上限 8：超限按"优先级最低 + 最老"淘汰，只有淘汰才算真消失。
- 等位区不参与家族清扫吗？**参与**——新一轮天气把台下旧批也清掉，两个世界一套家族语义。
- critical 永不进等位区（走覆盖层，既有规则不变）。
- 进展卡（bgtasks）这类 system 信息卡照常参与——它闪退的 bug 修好后，
  点开的行为 = 正常入场（放不下就等位 + 边缘条可见），语义自然统一。
- pilot 检测更新：DESKTOP_FULL 硬伤删除（不再存在这个失败态），新增提示项
  "等位区滞留超过 N 轮的内容卡"（提示排版压力，人工看）。

## 7. 分期（TDD，每期跑批回归）

- **W1 机制**：①闪退 bug 复现定位修复；②desk 等位区（staged 队列 + 挤出转等位 +
  入场 staged）+ reconcile 上台 + 家族/ttl/召回语义 + summary/getLayout 同步。
- **W2 呈现**：边缘提示条 + 台下清单卡 + 上/下台动画（右缘滑入滑出，可预测）+
  横幅文案升级。
- **W3 闭环**：card.focus 台下召回语义 + 触控声明 + pilot/RUBRIC 更新 + 跑批。
- 预算：`src/cards/` 现约 737/800——等位区约 +80 行，超线则按"机制进驻"惯例
  重新核算并记录理由。

## 8. 本轮补充（产品三条之外，我认为要一起做的）

1. **summary 同步**（§5）——不做的话模型会把"台下"当"没了"，重复建卡或瞎道歉。
2. **等位淘汰的告知纪律**——只有真消失才打扰用户，进等位不横幅（降噪）；
   现在"挤出即横幅"改成"淘汰才横幅"。
3. **focus 的召回语义**——不然"叫回"只能靠模型重建卡（数据可能已丢）。
4. **闪退 bug 先修**——它大概率是现有撤卡分支误伤，等位区上线前必须定位，
   否则新机制会把这个 bug 藏得更深。
