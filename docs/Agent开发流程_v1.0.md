# 平台新增 Agent 开发流程 v1.0

> 2026-08-25 从旅行助手的完整开发过程提炼(PRD → 方案 → 三轮 HMI 改版 →
> 四件套落地 → 六轮 pilot 收敛 → 实拍连环修)。它和绘本、媒体域、自动化
> 走的是同一条路,只是旅行这次走全了。**流程是从真实教训里长出来的,
> 每条注意事项后面都有一次实拍事故。**

## 第零步:先判断"要不要新建 Agent 实例"

平台上"新增一个 Agent"通常**不是**新建 `agents/*/manifest.ts` 实例。
绘本、旅行、媒体都落在 main-agent 上,形态是**四件套**:

```
技能(skills/xxx.ts) + 工具(config/tools.ts + integrations/xxxHandlers.ts)
+ 引擎(core/xxx.ts,可选) + 域仓(state/xxx.ts,可选)
```

真正新建实例的判据(三条有其一才建):独立人设(说话方式和主 Agent
冲突)、独立权限集(能碰的工具集合本质不同)、独立上下文(不该看到
主对话)。验收标准不变:新实例只挂 3 个 Tool,不改平台一行代码就能跑。

## 流程:Skill 先行,九步

> 顺序是有讲究的(2026-08-25 用户拍板):**先写 Skill 草稿定能力,再做其他。**
> Skill 是章法——写"模型每一步该做什么"的过程,就是在枚举它需要哪些
> 动词(Tools)和哪些屏显(卡片):写不下去的地方就是缺的能力。
> 旅行开发的实际教训也支持这个顺序:五步对话脚本本质就是章法草稿,
> 它一确定,travel.plan 的 lines/days 两种形状、create 的 watch 结构
> 全都自然推出来了;反过来先做工具再补章法,就会出现"工具都在、
> 模型却把行程念在嘴上"的脱节。

### S1 Skill 草稿:用章法定能力(最先做)

拿到 PRD 先写 `skills/xxx.ts` 的**草稿**——不求工具名精确,求把
对话走通:

- 按用户旅程写章法段落:每步"用户说什么 → 模型该干什么(动词)→
  屏上该有什么 → 嘴上说什么(附一个问题)"。
- 写的过程中随手记两张清单:**能力清单**(章法里出现的每个动词=
  一个待定义 Tool 的雏形,含"它的返回里必须有什么"——答案必须在
  返回里)和**显示清单**(每个"屏上该有什么"=一个卡片模板或阶段)。
- 边界当场写死:哪些动作到提醒为止、哪些要确认(灰)、哪些永不给(黑)。
- whenToUse 先起草(≤20 字)——起不出来说明这个 Agent 的触发场景
  本身没想清。

**产出:章法草稿 + 能力清单 + 显示清单 + 边界清单。**
后面每一步都是在兑现这三张清单;S8 用真实工具名回填成定稿。

### S2 需求翻译:把清单归到四类落点

产出一张**落点清单**,每条需求归到四类之一:

把 S1 的清单逐条归类,归不进去的说明抽象错了:

| 落点 | 判据 | 旅行的例子 |
|---|---|---|
| 数据(config/state) | 加能力=加数据 | 采样节奏表、监控四类、卡片模板 |
| 机制(core/integrations) | 不含任何"贴心逻辑" | 采样调度、趋势分析(只摆事实)、天气回填 |
| 策略(skill/prompt) | 做不做/怎么说归模型 | 确认即接管、一轮一个问题、verdict |
| UI(cards/screen) | 展示逻辑=纯函数配测试 | trip 卡三档、滚动单页 |

同时写死三件事:
- **明确不做**(边界):旅行的"到提醒为止,不下单不支付"写进了 Tool 契约
  (没有下单参数)而不只是文档——边界要落在机制上。
- **数据源选型**:真实 API 优先(用户纪律);零 Key 零注册优先
  (Open-Meteo 先例);国内上游永不走代理隧道(ABROAD 白名单);
  mock 破例必须"示例数据"标记+确定性可重放+作为真实 fixture 录制槽。
  **调研结论写死在方案里**(如"RapidAPI 免费层+国内覆盖+历史价格三者
  不可兼得"),否则日后反复重查。
- **不可兼得清单**:免费额度多小、锁不锁区、有没有历史,当场记账。

### S3 HMI 与对话脚本可视化——用户拍板前不写渲染代码

- 设计画布(artifact)出**真像素**设计稿:每个档位、每个阶段各一张,
  行驶/停车分开画。
- **对话脚本就是 S1 章法草稿的可视化**:一张五步表——用户说什么/
  屏上显示什么/嘴上说什么/遵守哪条纪律。画完发现和章法对不上,
  改章法草稿,不带着分歧往下走。
- 卡片三纪律预检:相邻两档内容必须不同;相似族共用骨架不共用密度;
  阅读方向决定长轴(列表竖卡)。
- pilot 场景**在这一步一起写**:机器人性格指令(如"被连环问就不耐烦")
  就是验收标准的可执行形式。

### S4 域仓(state/)

- 存的是**用户数据**;读写、上限淘汰、坏数据兜底、防御性拷贝
  (`{...t}`,外部引用不许穿透进仓),没有一行业务逻辑。
- 什么不进仓:每秒变的遥测(播放进度)、跟运行态绑死的东西
  (播放队列不持久化)。样本类数据按滚动窗淘汰(30 天),
  记住 localStorage 5MB 按 UTF-16 算、**写是静默失败的**。

### S5 Tools(兑现 S1 的能力清单)

- 定义在 `config/tools.ts`(纯数据),handler 在 `integrations/`。
- 权限分级:黑(永不注册)/灰(confirm,判据:不可逆/安全/金钱/他人)/彩。
- handler 预算:每 Tool < 40 行;协议客户端每个 < 200 行,超了通常是
  业务逻辑漏进去了。
- **卡 = f(仓)**:渲染出口唯一(paintXxx 函数),所有 handler 改完仓
  调同一个 paint——卡片永远和仓一致,"原地生长"自动成立。

### S6 引擎(core/,可选)

只判定与 emit,不认识 registry/pipeline(自动化引擎、采样调度先例)。
调度策略做成**数据字段**(everyMs/onBoot),不做成代码分支。

### S7 卡片模板(兑现 S1 的显示清单)

- 模板契约三件套:fields(数据形状)/forms(形态)/interactions(交互声明)。
- 机制生成的卡标 `systemOnly`;模型临场内容才走 card.show。
- forms **块只增不减**(放大不掉块),密度差异靠加块(herofull/dayfull)。
- 渲染分支写进 `screen/render.ts`,CSS 进 screen.html;展示逻辑抽纯函数配测试。

### S8 Skill 定稿(草稿回填)

- 把 S1 草稿里的动词换成真实工具名、参数形状、返回字段——章法引用
  的每个能力此刻都真实存在。
- whenToUse ≤ 20 字;正文 ≤ 40 行(纪律测试盯着)。
- 四不相混:Tool=能力,Skill=章法,persona=品格,记忆=事实。
- **章法住在技能包里,模型取了技能才看得见**——影响"第一句话怎么接"
  的规则(先给再问、发问节奏)必须上升到人设层或工具 desc/message 里。

### S9a 装配(最容易漏的一步)

**双装配检查单**:director/main.ts 和 tests/pilot/run.ts 两处都要接
(registry deps、引擎定时器、跨域组合如 geocode+天气)。
handler 必须带 NOT_WIRED 守卫:没装配返回人话 unavailable,
不裸抛 TypeError——拒绝必须携带机器可读原因,**没装配也一样**。

### S9b 验证闭环(全程,不是最后一步)

1. TDD 先红后绿,全量绿才算完成。
2. **画廊肉眼看**:溢出、空白、块缺失只有眼睛抓得到(单测只验到 blocks)。
3. pilot 跑场景:硬伤/提示分级;快照按出现次序配对。
4. **实拍 trace 复盘**:每条奇怪话术先查是不是指令在互相矛盾。
5. 新工具上线必跑一轮"参数退化观察":模型对新 schema 的第一批调用
   会暴露它的退化形态(字符串化数组、自造字段名、幻觉参数),
   这是**固定成本**,预算里要有它。

## 各层编写注意事项(每条背后是一次实拍)

### Tool desc / 返回 message

- desc 是**给模型的指令**,不是给自己的备忘录(元信息会被当话念出来)。
- desc 和人设打架时模型两边都想满足,结果两边都不对——查奇怪话术先查矛盾。
- 数组参数必须用 `items` 写 JSON Schema;报错要带"收到的键"和
  "正确形状示例"——一条鲜活的错误记录比 desc 重得多。
- **答案必须在返回里**,模型才没有理由再调一次(create 带 quotes、
  refresh 带 latest;缺了它模型会换着参数打转,熔断都拦不住)。
- 缺参一次报全,不挤牙膏;message 写人话,它直接进模型上下文。
- 状态提示走返回不走 system(travel.list 见 draft 提"下一步 create")
  ——判据必须是系统状态/数据形状,出现意图字符串比对即违规。
- 模型参数退化在 **registry 统一宽容**("24"→24、{item} 剥壳、
  字符串化数组、startDate→departDate),handler 里不许散装适配。
- 幻觉数据按形状拦(过去的日期不入仓、参数引用字面量不当地名)。

### 卡片 / 渲染

- 模板字面量里 `${cond ? x : ''}` 之间的换行会留空白文本节点,
  在 flex 里变匿名 item——**拼数组 .filter(Boolean).join('')**。
- `.bd` 全局 justify-content:flex-end:超高内容的头部会被推进
  **滚不到的区域**——长内容卡自带滚动容器(负 margin+同值 padding
  保出血头图)。
- svg 不锁高会被 intrinsic ratio 拉爆(spark 146px 吃掉半张卡)。
- 行驶中不给滚动——档位判据即滚动判据(hall 只给单行摘要)。
- 一次性字段在 render 合并语义下会残留:会消失的字段每次显式给
  undefined(绘本定妆照教训)。
- **画廊必须肉眼过**,而且画廊本身不能失真(多套一个标题栏,
  出血判断全是假的)。

### Skill / 交互

- 先给内容再问问题,一轮最多一个问题,问题的答案要能直接改卡。
- 确认即接管:认可就是授权,告知不询问,opt-in 变 opt-out。
- role 和 skill 的判据要同一把尺("出结果要几轮?一轮=就地办,
  多轮=转后台"),不然模型夹在中间两头误。
- 撤卡时机两类:问题卡用户一开口就撤;结果卡按"这件事翻篇"撤。
- Prompt 说两次不听就改机制(size 降级先例)——但机制修正只许
  发生在"建议层",用户意愿层保持拒绝。

## 对照旅行 Agent:符合度与缺口

九步旅行都走到了(只是顺序错了——Skill 是最后补的定稿,不是最先写的草稿),有五条是**事后补票**——它们就是这份流程要
前置的原因:

1. **S3 设计没先行**:第一版 HMI 是"最小渲染",用户拍照说"没实现还是
   很丑"才回头做设计稿。→ 流程规定:用户拍板设计稿前不写渲染代码。
2. **对话脚本后置**:审讯式连环问是上线后 pilot 抓的,五步脚本 v3
   才补。→ 脚本与 HMI 同步定,pilot 场景同步写。
3. **装配双份漏了 pilot**:NOT_WIRED 守卫是 pilot 裸抛 TypeError
   之后才发明的。→ S9a 双装配检查单。
4. **参数退化当成了意外**:{item} 剥壳、字符串化数组、startDate、
   过去日期……每个都是实拍才修。→ S9b 把"参数退化观察轮"设为固定步骤。
5. **"答案在返回里"领悟得晚**:refresh 不带价导致模型打转烧光轮次,
   是 v3 回归才破案。→ 写进 Tool 注意事项第一梯队。

仍然开放的(流程覆盖不了、要逐案判断):模型能力差异(同一套
desc/schema,Opus 一次对、便宜模型三连错——换模型是配置问题不是
代码问题);多 Agent 实例的真实需求还没出现过,第零步的判据没有
被真正检验过。
