# 语音链路整体设计:麦克风仲裁与作废语义补全

2026-08-18,由一份实拍日志触发:用户连发「导航去春熙路」「播放音乐」再点选候选,
旧轮的慢层在导航已设好之后重新弹出候选问题卡、同一句话术连发 6 轮烧光轮次上限。
产品结论:**声音需要一个统一的出口裁判**,就像卡片有布局仲裁一样。

## 现状盘点(修正过的事实)

| 声源 | 实际路径 | 缺口 |
|---|---|---|
| Agent 话术 | pipeline speaking 事件 → 屏端 speakAgent(排队/同文去重/插话即停) | 最有纪律的一路 |
| `voice.speak` 工具 | **纯回声**(registry 只返回文本,不发声;声音只经 speaking 事件) | 成功型打转无熔断:同文连调 6 轮全 ok,撞墙检测只看失败 |
| `voice.ask` 工具 | 建问题卡 + 文本回声 | stale 轮照样建卡——问题已翻篇还在弹 |
| 绘本朗读 | 屏端 storyReading 占麦 | 只有"占麦"一档,确认问句插不进去 |
| 后台交付播报 | 面板 voiceBusy 排队 → speaking 事件 | 与屏端队列是两套互不知道的排队(v1 不动,记入后续) |
| 媒体音频 | `<audio>` 独立 | TTS 说话时不压低——真车播报必 duck |

## 决策

### 1. 优先级表(上打断下,同级排队)

1. **用户开口**——最高打断力:turn/confirm/delivery 立停清队;绘本豁免(有自己的翻页节奏)
2. **确认问句**(MRTR / voice.ask)——可打断绘本页;被打断的页在确认结束后**从头重读**
3. **当前 turn 话术**——同轮排队说完整、同文去重;新 turn 清旧队(现状)
4. **绘本页**——占麦期间 3 号**丢弃**(衔接话术过期即无意义,不排队)
5. **后台交付**——只捡空闲说(v1 沿用面板 voiceBusy)
6. **媒体音频**——永远让位:任何 TTS 开口 duck 到 20%,说完渐回

决策收在屏端纯函数 `micAct`(张嘴的地方做单写者,绘本这类不经 pipeline 的声源漏不掉),
执行是薄层。

### 2. 作废语义:「话」与「活」分开

- `stale`(用户插话):车控类活照干完;**mic 类工具(voice.speak/voice.ask)拒绝**
  (`STALE_TURN`,SELF_FIX 级)——说话就是抢麦,建问题卡也是。哪些工具算 mic 类
  由 `ToolDef.mic: true` **声明**(模板特性归声明的先例),pipeline 不点名工具。
- `discarded`(清空会话):一切作废,现状不变。

### 3. 成功型打转熔断

同一 turn 内、相邻两轮、同工具+同参数、上轮已 ok → 本轮**先斩**为
`REPEAT_CALL`(SELF_FIX):"刚成功过,别重复,收尾即可"。
- 判据是调用签名(系统状态),不解析内容。
- 一轮内并行的重复调用不拦(连跳两首歌是一轮两个调用);跨 turn 不拦(新输入=新意愿)。
- 与既有撞墙熔断组合:REPEAT_CALL 连续 3 次自动跳最后一轮。

### 4. 待答状态直达慢层

屏幕点选合成的输入(候选卡/问题卡的回答)**跳过快层**——快层对"第4个"无事可做
(实拍编造 placeId 白烧 3.6 秒)。复用「pending MRTR 直达慢层」先例:输入来源
(屏端合成)是系统状态,不是意图。落点:`run(text, { answer: true })`,面板点选路径传入。

## 明确不做(v1)

导航播报(产品裁定)· 多音区 · 混音 · 面板/屏端双队列合并(记入待办)·
trace 展示按世代归位(纯展示,另行)。

## 测试要点

micAct 全矩阵;stale 下 mic 工具拒且不建卡;repeat 熔断三条边界
(相邻轮拦/同轮并行不拦/跨 turn 不拦);answer 输入 fast 零调用;
duck 与绘本重读为屏端薄层,浏览器实测。
