SECTION 01

一背景

为什么做这个东西？三个很实际的痛。

周期太长设计 → 实车

一个产品点从设计到真正能体验，最少半年。BUG 和设计问题都得等半年后才看得见，那时候改，代价翻倍。

文字讲不清产品 → 研发

研发老问：这里到底是模型自己决策还是写死规则？交互出来长什么样？这些靠文档真讲不明白，理解偏了就直接写进代码了。

Demo 各自为政产品线之间

每个产品都拿自己顺手的 Agent 搭 Demo：没有车辆信号、没有语音流程、也没有应用之间的仲裁。Demo 做得再好，搬到车机上还是得重来。

SECTION 03 · A

Agent 架构：快慢双层

跟人一样：条件反射归快层，要动脑子的归慢层。但用户感觉到的，永远只有一个助手。

一句话进来之后
🎙 用户开口或者点屏幕
→

快层小模型 · 27 个高频工具 · 秒级

  • 只挂安全的"彩"权限操作，能干的马上干、马上答
  • 快归快，边界卡在权限分级上，出不了事
  • 干不了的立刻移交，不磨蹭
→

慢层大模型 · 工具按需取用

  • 把快层干的活检查一遍，剩下的接着干
  • 都对、没新增？那就不说话 —— 沉默也是答案
  • 耗时的活拆给子 Agent 后台跑，快活先交付
每轮干完就移交，两层看同一份对话记录 · 用户中途插话？旧活照干完，就是不抢话
工具注册表权限把关 · 该确认的弹确认
技能包 ×8目录常驻，用到才展开
子 Agent后台跑，跑完自动来报
四级记忆信号 → 会话 → 领域 → 偏好
决策全在 Prompt 里 · 代码里出现意图判断就算违规 拒绝要带原因和建议 · 模型拿着就能给替代方案 只记用户明说的 · 不搞自动揣摩

SECTION 03 · C

语音链路：全系统就一个「嘴」

谁想说话都得先排队，不会出现两路语音抢着说；用户一开口，谁都得让。

声音仲裁
confirm
确认询问 —— 涉及安全的问句最优先
turn
对话回复 —— 但不许打断讲故事
story
绘本朗读 —— 被打断的那页从头重念
delivery
后台任务来报 —— 嘴忙就等着
→
声音仲裁唯一出声口
用户开口 = 最高打断力
（讲故事豁免）
→
TTS 播报一开口音乐自动压到 20%，说完复原
字幕按句子一页页上屏，不搞跑马灯
星河角标听 / 想 / 说 / 等确认，看一眼就知道它在干嘛
角落的确认按钮就是确认卡的投影，点按和开口说，走同一条路 屏幕上摆着的不逐条念，嘴里只说关键差别 播报被打断，字幕跟着一起停
SECTION 03 · D

HMI & 桌面：卡片是带契约的投影

桌面不是 Agent 想摆啥摆啥 —— 基础卡跟着车辆状态走，规则驱动，模型不插手。原则就一条：可预测比好看重要，演示的人得能预判结果。

12×8 统一栅格 · 96 单元
导航 · 左锚定，挤不走
媒体 · 分源查表
天气 · 逐时预报
候选列表 · 能点
自动化任务
指标卡
14 个形状 · 跨度和起点都取偶数 → 空隙一定是偶数宽，最小的卡永远塞得进去，不会出现死缝 · 右上角 −/＋/✕ 用户自己调 · 有卡走了，空位自动往左上回填，不留洞
模板有契约

数据长什么样、每个尺寸放什么内容、哪里能点 —— 全是声明出来的，不是代码里临时判断

急事优先

紧急告警放不下就走覆盖层，绝不弹"桌面已满"；普通卡放不下就先排队，有空位自动上来

模型直出的卡（canvas）

应对没有模板的长尾需求，四道闸兜底：消毒 → 容量 → 缩放 → 文字兜底；开车时不给滚动

显示三通道 · 内容和"说一声"分开走
卡片正经内容：导航、媒体、候选、天气
横幅说一声就完："车窗开了"、为什么没做成 —— 不占桌面格子
覆盖层真出事了才用：安全告警、全屏内容
SECTION 04

四演示：九个 Case，把能力都过一遍

每个 Case 就是一句话开场，全在同一台"车"上连着演，不用切环境。

CASE 01 · 秒级车控与权限分级
有点热，开点窗，空调调到 24 度
快层一秒把两件事都办了，顺口确认一句。接着说"把车门打开"——这是灰权限，屏上弹确认卡，点头才执行。开车的时候，连开窗都会自动升级成要确认。
快慢双层彩/灰权限确认流回执横幅
CASE 02 · 约束引擎与安全红线
（开车时）放个电影 / 帮我踩一脚刹车
开车看视频？约束引擎直接拦，Agent 会好好说为什么，还给替代方案（"先听音频版？"）。让它踩刹车？这个工具压根不存在，它只会说这事得驾驶员自己来。
约束引擎安全红线拒绝带原因
CASE 03 · 导航全链路
找个附近有饺子馆的充电站，顺便看看哪条路不堵
真实高德接口：先搜充电站，拿着坐标再搜饺子馆 —— 没人预置过这个"意图"，是模型自己组合出来的。候选上屏能点，比完路线设目的地，导航卡自动出来、实时 ETA。
真实高德 API工具组合卡片点选
CASE 04 · 媒体多源与桌面仲裁
放首周深的歌 … 换成新闻 … 声音小点，下一条
音乐、电台、播客、新闻、视频一套播控随口切；歌词唱到哪亮到哪，封面颜色晕进卡片。桌面上卡多了自己会挪位、排队，不乱。
20+ 真实内容源换源无缝等位区布局重力
CASE 05 · 插话打断
关闭空调 ——（不等回话）—— 再把车窗关了
连说两句不等回话，两句都会执行 —— 插话只是不抢话，不会把上一件事扔了。你一开口，播报立刻让路，音乐自动压低。
插话不丢活语音仲裁
CASE 06 · 生成式卡：没有的功能现场造
给孩子来个算 24 点的小游戏，再帮我查下今天美股怎么样
小游戏没有现成工具？模型现场写一个放上屏。查行情这种慢活扔给后台子 Agent 跑，查完自动来报 —— 快活不用等慢活。
生成式 UI后台并行任务芯片
CASE 07 · 自动化：用嘴建规则
以后下雨就自动关窗；每天下午四点把空调打开
规则用嘴建，存下来就是用户自己的数据。控制面板上一注雨，当场看规则触发、车窗关上、横幅报一声。规则卡上能直接开关，任务码还能分享给别人。
自动化引擎到点就触发现场注入信号
CASE 08 · 记忆与偏好
记住我喜欢 24 度 ——（重启会话）—— 有点冷
说一句"记住"，就真记住了。换个会话说"有点冷"，它照着你的偏好调到 24，不瞎猜。播放队列、上回聊到哪，也都各有各的记法。
四级记忆跨会话
CASE 09 · 路上的故事：AI 儿童绘本
给妹妹讲个她当主角的故事吧
拍张照定妆（家长点头才用），孩子自己当主角，每章讲完让孩子接着编往下走。快到站自动收尾，一键导出 H5，发给爷爷奶奶双击就能看。
多模态生成孩子共写H5 交付物

建议演示动线（12 分钟左右）

  1. 01 车控 + 02 红线开场 —— 90 秒让人信"这是台真车"，顺便把权限分级讲完；
  2. 03 导航 → 04 媒体连着放 —— 真实接口和桌面编排全在这段自然出现；
  3. 05 插话 + 06 生成式卡 —— 正面回答研发那两个问题：什么时候模型决策、交互长什么样；
  4. 07 自动化 + 08 记忆 —— 平台能沉淀东西：规则和偏好都是用户自己的数据；
  5. 09 绘本收尾 —— 一个完整的新产品，接进来只加了数据和 Prompt，平台一行代码没改。
