## 2. 设计语言

**底色下沉 · 卡片浮起 · 数字发光 · 标题让位**

单一浅色主题，**不做日夜切换**（沿用 CLAUDE.md 既有约束）。

1. **底色压暗、卡片描边加阴影。** 原来 `#EEF1F6` 底 + 纯白卡 + 零边框零阴影，卡片边界只靠明度差，投影演示时看不见边。
2. **标题降级、图标升级。** 标题从 `30px/600/主色` 降到 `24px/500/--tx-3 + 0.09em 字距`；原来的 9px 小圆点换成 **40px 语义色图标块**。视觉重心让给数值。
3. **数字是主角。** 核心数值统一 `--t-num` 起跳 / 600 字重 / `tabular-nums` / `-1.5px` 字距；单位 `0.44em` / 400 字重 / `--tx-3`。
4. **语音区底色下沉。** `--sf-sunken` + 上边界 hairline + 顶部高光，"这里是对话区"成为空间事实而不是靠动画。

## 3. Design Token

### 落地方式（关键约束）

`build-single.mjs` 只替换 `<script type="module">` 标签，**外部 `.css` 文件在单文件版会整个丢失**。所以：

> Token 定义为 `src/design/tokens.ts` 导出的 **CSS 文本常量**，两个入口（`src/screen/main.ts`、`src/director/main.ts`）启动时注入 `<style>`。esbuild 打进 iife，双击版照样带得走。

完整取值见视觉稿 `:root`，可直接抄。

### 三层结构

**① 原始色板**（无语义）：`--n0…--n10` 11 阶中性色。

**② 语义色**：每类四件套 `--{n}-fg / -bg / -bd / -gr`（前景 / 底 / 边 / 渐变）
`brand` · `info` · `ok` · `warn` · `danger` · `media` · `pick` · `sys`

拆开第 5 条诊断：系统卡 = `sys`、提示 = `info`、约束不满足 = `warn`、拒绝 = `danger`、执行成功 = `ok`、选择/待选 = `pick`、媒体 = `media`。

**③ 字阶（核心机制）** —— 一次性解决诊断 1 和 2。

7 阶语义字号，**不写死 px，乘以卡片单位 `--u`**：

```css
--t-cap:22px  --t-body:26px  --t-title:24px  --t-lead:38px
--t-num:52px  --t-hero:76px  --t-mega:100px

.s-chip{--u:.86}  .s-strip{--u:.92}  .s-bar{--u:.96}
.s-card{--u:1}    .s-wide{--u:1.06}  .s-panel{--u:1.12}
.s-banner{--u:1.18} .s-tower{--u:1.06} .s-stage{--u:1.30} .card-full{--u:1.45}

.card h3{font-size:calc(var(--t-title)*var(--u))}
```

31 条 `.sz-*` 覆盖规则里，**字号相关的全部删除**，只保留形态差异（如小卡转向条改横向堆叠）。加新模板不用再手写全尺寸覆盖。

**圆角也跟着档位走**：chip/strip/bar `--r-s:20px`，card/wide/panel/banner `--r-m:28px`，tower/stage/full `--r-l:36px`。393×237 的 chip 配 32px 圆角会像药丸。

### 字体

零依赖 + 不联网加载（导航卡的高德 JS SDK 是唯一例外），所以仍用系统栈但收紧：

```css
font-family:"PingFang SC","Noto Sans CJK SC",-apple-system,"Segoe UI",sans-serif
```

两件必做：
- **所有数字容器加 `font-variant-numeric: tabular-nums`**。现在只加了 6 处，ETA 从 28 跳到 27 时会左右抖
- 字重收到 400/500/600/700 四档，**删掉天气大数字那个孤立的 300**（车机上远看发虚）

### 渐变分四层，各有上限

| 层 | 用在哪 | 幅度上限 |
|---|---|---|
| **环境底板** | 桌面背景两个径向光晕（左上暖、右下冷） | **ΔL < 4%** —— 再大白卡就显脏，这是硬上限 |
| **卡片瓷面** | 162° 微渐变 + `inset 0 1px 0 rgba(255,255,255,.92)` 顶部高光 | 白 → `#F7FAFD` |
| **语义色晕** | 每卡右上角一团身份色径向渐变 | **7.5% 透明度** |
| **强调渐变** | 进度条 / 播放主按钮 / 转向箭头 / 图标块 / 序号圆点 / 电池 | 145° 双色 + 同色发光阴影 |

**数值文字只有天气大温度允许渐变**（黑→青），其余一律实色。车机远看时渐变文字掉可读性。

## 4. 栅格与档位

### 12 列 × 4 行 = 48 单元

桌面区 2440 × 996px，gutter 16px ⇒ **单元 188.7 × 237px**。

把「排版栅格」和「尺寸档位」拆开（印刷栅格的做法）：栅格细，只管像素对齐，Agent 看不见；档位粗，Agent 和规则只能从 10 档里选。

| 档位 | 列×行 | 像素 | 屏占 | 旧名 | 典型用途 |
|---|---|---|---|---|---|
| `chip` | 2×1 | 393×237 | 4.2% | — | 单值反馈 |
| `strip` | 4×1 | 803×237 | 8.3% | — | 单行结果、小转向条 |
| `bar` | 6×1 | 1212×237 | 12.5% | — | 通栏提示、新闻标题 |
| `card` | 4×2 | 803×490 | 16.7% | **1/6** | 车控组、天气、播放器 |
| `wide` | 6×2 | 1212×490 | 25% | — | 列表双列、生成式默认 |
| `panel` | 8×2 | 1621×490 | 33.3% | **1/3** | 大列表、确认卡 |
| `banner` | 12×2 | 2440×490 | 50% | **1/2** | 通栏 |
| `tower` | 4×4 | 803×996 | 33.3% | — | 全高窄：导航旁的播放器 |
| `stage` | 8×4 | 1621×996 | 66.7% | **2/3** | 导航地图、视频 |
| `full` | 12×4 | 整屏覆盖 | 100% | **full** | 能力目录 |

**旧档位一个都没变形。** 老的 (w,h) 乘以 (4,2) 正好落在新栅格上，像素误差 < 1%（797×486 → 803×490）。导航卡仍是 stage 左锚定、右侧仍恰好放下两张 card。**分数名保留为别名**，Tool 参数、模板 `defaultSize`、Agent Prompt 里的老写法继续有效。

新增 5 档全在原来的空档里：最小卡从 16.7% 降到 4.2%（小 4 倍），档位梯度从 4 档变 10 档。

### 不产生碎缝的不变量（必须写进 `src/core/` 的不变量断言）

1. **所有档位宽度为偶数**（2/4/6/8/12），无一例外
2. **列起点必须是偶数**（0/2/4/6/8/10），6 个合法列位

⇒ 任意排布后的空隙**必然是偶数宽**，而最小档 `chip` 就是 2 宽 ⇒ **任何空隙都填得上，永远不会出现填不进任何卡的死缝**。

行方向：
- 全高档（4 行）起点必须为行 0
- 半高档（2 行）起点 ∈ {0, 2}
- 单行档（1 行）起点 ∈ {0, 1, 2, 3} —— 能起在任意行，跟半高卡并排时形成错落，这是刻意的

### 降级阶梯

```
chip ← strip ← bar ← card ← wide ← panel ← banner
```

`tower` / `stage` / `full` 是专用档，**不进阶梯**（跟今天的 2/3 一样）。

抢位时卡片能一档一档地让，而不是从通栏直接崩成小方块。

### 放置算法

沿用 `desk.ts:104` 现有的确定性扫描，只是网格变细：全高档最先 → 优先级降序 → 创建时间升序 → 行优先扫第一个合法位置。搜索空间从 6 个位置涨到 6 列位 × 4 行位 = 24 个，仍可穷举测试。

### `desk.summary()` 要改写

"剩余 20 格"在 48 单元下对模型毫无意义。改成用档位说人话：

```
桌面：导航(stage) · 播放器(card)。右下角还能放 1 张 wide 或 2 张 strip
```

## 5. 内容填充规则（解决诊断 9）

> **标题在顶，数据坐底，内容块均分高度。**

1. `.bd { justify-content: flex-end }` 成为默认。单值卡的大数字锚在底部，不再浮在中间上下两头空。
2. 多项内容用 `display:grid` + `grid-auto-rows:1fr` 的**块状均分容器**，块数由 item 数决定：

| items | 布局 | 例 |
|---|---|---|
| 1 | 整卡一个大数值（`--t-hero`） | 方向盘加热 |
| 2 | 上下两块 | |
| 3 | **主块跨两列** + 2 小块 | 空调：温度大块 + 风量 + 出风 |
| 4 | 2×2 | 车窗四扇 |
| 5–6 | 3×2 | 座椅 |

每块是浅底渐变 + hairline + 18px 圆角的小容器，内部 `space-between`：图标+标签在上、大数字在中、进度条贴底。**行数变了高度自动重分，不需要为每种 item 数写一套 CSS。**

## 6. 自适应显示：形态函数

`src/screen/layout.ts` 从 3 个函数补到 11 个（每个模板一个），**签名从 `(size)` 换成 `(cols, rows)`**：

```ts
export interface Form { blocks: string[]; maxItems?: number; overflow?: 'more'|'count'|'none'; cols?: number }
export const CARD_FORMS: Record<string, (cols: number, rows: number) => Form>
```

宽度只有 5 种取值（2/4/6/8/12），高度只有 3 种（1/2/4），每个模板实际只关心 2–3 个阈值。**按阈值判断而不是查表**，否则 11 × 10 = 110 组手写不可行：

```ts
listForm(cols, rows) {
  const lines = rows === 1 ? 1 : rows === 2 ? 4 : 9
  const twoCol = cols >= 6
  return { maxItems: lines * (twoCol ? 2 : 1), overflow: 'more', cols: twoCol ? 2 : 1 }
}
```

### 溢出策略（解决诊断 7）

屏幕不可交互，`overflow:auto` 等于内容永远看不到。三种策略按模板声明：

- `more` —— 列表类：截断 + 底部固定一行「还有 N 条没显示」
- `count` —— 能力卡：只报数量
- `none` —— 正文类：靠 `--u` 缩字号

**「还有 N 条」不只是 UI**：必须同时回给 Agent，写进 `desk.summary()` 注入上下文。否则模型以为屏上有 12 条、说「第 10 个」，用户根本看不到。

## 7. 显示优先级与三条通道

### 来源 ≠ 紧急度

现在 `PRIORITY = {task:2, rule:3, system:4}` 描述的是**谁建的卡**。后果：车门没关且已起步的安全告警，跟天气卡同为 `rule`，抢位时按 LRU 决定谁活——错的。

`src/config/priority.ts` 加正交的 `urgency` 维度：

| urgency | 含义 | 行为 |
|---|---|---|
| `ambient` | 背景信息（天气、播放器） | 可被挤、可缩到底 |
| `normal` | 常规反馈（车控、列表） | 默认 |
| `urgent` | 需要用户回应（确认、待选） | 不可挤，最小 `card` |
| `critical` | 安全相关（车门未关、约束拒绝） | 不可挤，最小 `panel`，同时触发横幅 |

`最终优先级 = kind 权重 + urgency 权重`，抢占顺序表写成数据。`urgency` 由 `cardRules` 声明或 `card.show` 传入，默认 `normal`。**不允许出现意图分支。**

### 三条通道（解决诊断 6）

| 通道 | 用途 | 位置 | 并发 |
|---|---|---|---|
| **卡片** | 常态信息与结果 | 48 单元桌面内 | 多张 |
| **横幅** | 拒绝原因、约束不满足、能力缺失、卡片被挤出的告知 | **锚定桌面区顶部**（`top:128px`，跟着 `--voiceH` 走，不会浮空） | 一次一条，排队 |
| **覆盖层** | `full` 内容卡 / `critical` 告警 | 整屏 | 一次一个，拆成 `content` / `alert` 两种视觉 |

横幅按语义色分色：`danger` 拒绝 · `warn` 条件不满足 · `info` 系统提示 · `ok` 执行完成。现在这四种全是橙色。

### 选择卡的状态感

1. **待选态**：整卡 `pick` 色描边 + 呼吸动画（2.2s）
2. **倒计时**：`voice.ask` 有超时时，卡片底部 5px 进度条走完
3. **序号色独立**：序号圆点用 `--pick` 而不是 `--brand`，跟转向条区分
4. **chip 档不显示选项，只显示计数** —— 放不下的选项被用户「第 4 个」点到就是事故

撤卡时机沿用 CLAUDE.md「跑批跑出来的三条经验」第 3 条，不动。

## 8. 动效体系

车机 HMI 一律 **≤400ms**，主曲线 `cubic-bezier(.22,.61,.36,1)`，进场允许轻微过冲 `cubic-bezier(.34,1.26,.64,1)`。

| 事件 | 动效 | 时长 |
|---|---|---|
| 卡片进场 | `translateY(20px) + scale(.95)`，多张卡 **45ms 错峰** | 340ms |
| 卡片退场 | 先缩到 .94 再淡出，动画结束才移除节点 | 220ms |
| **栅格移位** | **FLIP** | 380ms |
| **档位缩放** | FLIP，宽高一起插值 | 380ms |
| 进度条 | `width` transition | 380ms |
| 待选卡 | 描边呼吸 | 2.2s |
| 倒计时 | 底部走条 | 按 timeout |
| 直播点 / 语音状态点 | 脉冲扩散 | 1.8s |
| 思考态 | 语音球外圈 conic 渐变旋转 | 1.6s |
| 横幅 | 从上方滑入带回弹 | 340ms |

### FLIP（唯一有技术含量的一条）

CSS Grid 的 `grid-row/grid-column` **不能 transition** —— 现在 `renderDesk()` 改完位置卡片是**瞬移**的，导航卡一来天气卡直接从左上闪到右下。

做法：DOM 更新前记录旧 `rect`，更新后记录新 `rect`，用反向 transform 把元素"拉回"旧位置再动画归零。约 40 行纯函数，可测。

**两个坑，实现时必须处理**：

1. **舞台是 `scale()` 过的。** `getBoundingClientRect()` 返回缩放后像素，而 transform 作用在元素本地坐标系 —— `dx/dy` 必须**先除以舞台缩放比**，`sx/sy` 是比值不受影响。
2. **车窗过渡动画每帧调 `renderDesk()`。** FLIP 每帧跑会打架 —— **只在栅格坐标真变化时触发**，比较节点上存的 row/col，纯数据刷新不触发。

参考实现见视觉稿第一屏的 `paint()` 函数，可直接搬。

## 9. 生成式 HMI

模型遇到 11 个模板都装不下的临场内容时，**直出 HTML/SVG 片段**。

> **产品已知并接受的代价**：这跟「可预测优先于最优」正面冲突，同一句话两次演示可能长得不一样。下面的设计是在保住安全和排版一致的前提下，把不可预测性变成**可测量**的。

### 机制

新模板 `canvas`，`data: { title, html, hint? }`，默认档位 `wide`。

**渲染进 Shadow DOM**：`attachShadow({mode:'open'})` 天然做样式隔离 —— 模型写的 CSS 漏不出去，桌面样式也不会污染它，同时 `font`/`color` 仍从外部继承，所以它默认就长得像这套系统。零依赖，浏览器原生。

Shadow root 注入一份**画布契约样式表**：Token 变量 + 基础排版复位 + `:host{display:block;height:100%;overflow:hidden}`。

### 消毒器 `src/screen/sanitize.ts`（约 120 行纯函数）

用 `DOMParser` 解析后遍历树，白名单放行：

- **标签**：`div span p b i em strong small h4 h5 ul ol li table thead tbody tr td th br hr img figure figcaption` + SVG 全族（`svg g path rect circle ellipse line polyline polygon text tspan defs linearGradient radialGradient stop clipPath use`）
- **禁止**：`script iframe object embed link form input button select textarea meta base`，**含 `<style>`** —— 样式只允许 inline `style` 属性，避免模型写出影响 `:host` 的选择器
- **属性白名单**：`class style width height viewBox d fill stroke stroke-width opacity transform x y cx cy r rx ry points offset stop-color gradientUnits x1 y1 x2 y2 text-anchor font-size font-weight alt src`
- **一律剥离**：任何 `on*`、`xlink:href`、`href`
- **`src`**：只允许 `https:` 与 `data:image/`
- **`style` 值**：禁 `url(`、`expression(`、`position:fixed`、`@import`

消毒后为空 → **退回 `generic` 卡渲染 `text`**，绝不白屏。

### 尺寸契约（不做则模型必溢出）

Tool 描述里把**当前卡片的真实像素**告诉模型：「你拿到一块 1212×490 的画布，不能滚动，超出部分会被裁掉」。像素由档位算出注入，是数据不是分支。

### 可测量化

- pilot 加一条**硬伤**检测：`canvas` 卡渲染后 `scrollHeight > clientHeight` 即报「生成式卡溢出」
- 消毒器记录被剥离的标签/属性，写进控制面板的 trace

### 顺手修 bug

### 播放器控制条的两条约定（重要）

**（1）控制条不是按钮。** 屏幕 `cursor:none` **不可交互**，本次重设计**不引入触控**。控制条画成**低对比图标 + 当前态高亮**的状态指示，视觉上不像按钮；电台卡底部加一行 `◎ 说「换一台」「大点声」都可以`，把它标成语音能力。

这一行顺带填了 CLAUDE.md「能力曝光度统计未做」的一半。**pilot 的「让用户点屏幕」硬伤检测保持不变。**

**（2）进度条不进 store。** CLAUDE.md 明确「播放进度不进 store」（position 每秒变好几次，进信号系统就是每秒重评规则）。所以进度条**由车机屏本地的 `<audio>` 元素自己渲染**：`src/screen/player.ts` 读 `currentTime`，走展示层不走信号，约 +15 行 rAF 回调。这条守住了「状态 vs 遥测」的界线。
