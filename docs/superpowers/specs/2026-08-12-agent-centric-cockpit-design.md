# 以 Agent 为主的座舱：显示 · 状态 · 记忆 · 交互的统一设计

> 2026-08-12 ｜ 上游：[2026-08-10 卡片编排](./2026-08-10-card-orchestration-design.md) ·
> [2026-08-11 媒体域](./2026-08-11-media-domain-design.md) ·
> [2026-08-11 HMI 重设计](./2026-08-11-hmi-redesign-design.md)
>
> 本设计源自一轮完整的架构评审（含实测取证），覆盖四个维度：**Agent · Tools · HMI · 记忆系统**。
> 核心诉求：构建以 Agent 为主的座舱 —— HMI 是 Agent 的脸，Tools 是 Agent 的手，
> 记忆是 Agent 的连续性，四者不是并列的模块而是一个主体的四个面。

---

## 0. 公理（先于一切条目）

1. **卡片是"带契约的投影"，不是容器。** 全系统唯一的容器是 `canvas-app`（沙箱逃生舱），
   它的存在意义恰恰是让其它卡片**不必**升级为容器。数据层集中（信号 + 域仓）、
   逻辑层集中（handler/规则 = 机制，Prompt = 策略）、样式层集中（token + 模板 CSS）——
   MiniApp 化会从后门把"APP 化"请回来，而无APP化是这个产品的立身之本。
2. **模型的世界观必须由结构保证，而不是纪律约定。** summary 与像素的一致性靠"同一份公式
   两端消费"，不靠"记得两边同步改"。本次评审实测到的 12 vs 4 分裂（能力目录）是第三次
   踩同一个坑，本设计从结构上根除这一类问题。
3. **降级与恢复必须对称。** 现状只有降级半边（缩、挤、退），恢复半边整个不存在——
   实测：天气卡被压到 chip 后清空桌面 5/6，它永远停在 chip；播放器被挤掉后
   `media.playing` 仍为 true 却再也回不来。**这违反"桌面 = f(车辆状态)"**，
   桌面成了 f(状态, 历史路径)。
4. **模型不该被叫醒的事，一件也不要叫醒它。** 自动续播、恢复重排、操控类触控（暂停/下一首）
   全部走机制层。判据：这件事有没有"理解"的成分——没有就是机制。

## 1. 四支柱与职责边界

```
                    ┌─────────────────────────────────┐
                    │            Agent（策略）          │
                    │  决策 · 话术 · 临场内容 · 何时问   │
                    └──────┬──────────────┬───────────┘
              看见的世界     │              │  伸出的手
        summary + 记忆注入   │              │  Tools（全部能力）
                    ┌──────┴─────┐  ┌─────┴───────────┐
                    │ 记忆系统    │  │ Tools（机制）     │
                    │ 四级，见 §2 │  │ 读写信号与域仓     │
                    └──────┬─────┘  └─────┬───────────┘
                           │              │
                    ┌──────┴──────────────┴───────────┐
                    │        HMI（Agent 的脸）          │
                    │  三通道投影 · 零业务逻辑            │
                    │  上行只报事实：设备事件 + 用户动作   │
                    └─────────────────────────────────┘
```

| 支柱 | 职责 | 明确不做 |
|---|---|---|
| Agent | 理解、决策、话术、临场卡片、何时向用户提问 | 不搬数据、不算布局、不管续播 |
| Tools | 机制：读写信号/域仓、返回契约、MRTR | 不做贴心逻辑（原则 1 不变） |
| HMI | 投影：卡片/横幅/覆盖层，动效，交互采集 | 零业务逻辑（硬约束不变） |
| 记忆 | 瞬时/会话/领域/长期 四级，供上下文注入 | 不自动学习（显式记忆，见 §2.4） |


### 1.5 四支柱之外（本节回答"还有别的吗"）

**信任与安全 —— 第五支柱，已建成待命名。** 约束引擎、黑/灰/彩、MRTR、机器可读拒绝、
消毒器、iframe 三铁律、隐私检测、挤出告知——它们散在四个支柱里，却是同一个关切：
让 Agent 的每次行动可预期、可拒绝、可解释。这是"车规座舱"区别于"聊天机器人"的一层。
命名的意义：安全逻辑跨支柱，评审要有一根线串着看（canvas-app 三铁律是这根线的最新一节）。

**主动性 —— 下一个该立项的能力维度。** 现系统纯反应式。关键判断：**不需要新架构**——
CardRule 的 `{when 三元组 → 动作}` 形状就是触发器，差的是把写权限从配置文件开放给
用户的话：`trigger.set` 把"等我降到 60 就开窗"写成数据，watcher 到点执行，
灰权限照走 MRTR，黑名单照样永不注册。条件是数据不是意图分支，硬约束全部不破。
触发器本质是"带条件的记忆"，与 `src/state/` 共享存储。本设计不含它，但记忆系统的
存储设计为它预留形状。

**评测 —— 场外的方法论支柱。** pilot/RUBRIC 已是事实上的第五子系统，本设计的每个
判断都被跑批证实或证伪过。Agent 座舱没有评测就没有迭代方向，只有观感。

**暂不升格**：真实语音链路（HMI 的听觉半边，接真语音时再立）；用户身份与隐私
（**记忆按单用户/主驾假设**，说话人机制已存在，将来分人有挂点——此假设写进 §2 边界）；
多 Agent（manifest 插槽已留好，需求出现前不立空架子）。生态接入留在 Tools。

## 2. 记忆系统（新立的一层）

### 2.1 四级分类学

| 级 | 内容 | 载体 | 持久化 | Agent 怎么看见 |
|---|---|---|---|---|
| 瞬时 | 车辆状态（车窗、当前曲目） | 信号 store（现有） | 否 | 上下文状态段（现有） |
| 会话 | 上一轮候选、指代对象、最近动作 | `src/state/session.ts` | 否 | summary 尾部"最近发生"摘要 |
| 领域 | **播放队列 · 播放历史 · 收藏 · 常用地址** | `src/state/domain.ts` | localStorage | Tool 查询 + summary 一行 |
| 长期 | 偏好（"空调默认 24""别对着脸吹"） | `src/state/prefs.ts` | localStorage | **system prompt 注入** |

**为什么不进信号 store**：store 的边界注释早写明"这条界线不划清，车速转速电流都会往里挤"。
队列/历史/偏好不是车辆状态，是内容域数据。信号对齐 VSS，域仓不需要也不应该对齐 VSS。

**单用户假设**：记忆默认属于主驾，本期不分说话人（副驾说"记住 24 度"也记入同一份）——
说话人机制已存在，将来分人时在域仓加 owner 维度即可，此处显式记下这个边界。

**持久化先例**：常用地址、城市选择已用 localStorage，不是新发明。收藏现在是内存数组
（实测刷新即丢），搬进域仓顺带修掉。

### 2.2 播放队列（修掉"诚实的残端"）

现状取证：`media.control` 声明了 next/prev 但返回 `NO_QUEUE`；`media.queue` 的描述自己承认
"这台车一次只放一首"；车机屏上报的 `ended` 事件**没有任何消费者**——设计边界当年写了
『"放完了"是事实，"该放下一首"是决定，归控制面板侧规则管』，那条规则从未建成。

设计：

```ts
// src/state/domain.ts
interface Queue {
  items: QueueTrack[]      // 同批搜索结果整批入队
  cursor: number
  origin: 'search' | 'favorites' | 'history'
}
```

- **入队**：`music.play` 命中某首时，把**同一批**搜索结果全部入队，cursor 指向命中项。
  `video.play` 同理。radio 是直播，无队列（next/prev 保持现状：拒绝并建议「直接说换哪个台」）。
- **续播是机制**：director 收到 `mediaEvent:'ended'` → `queue.next()` → 直接写媒体信号组
  开播下一首。**不叫醒模型**。尊重 `media.mode`（顺序/单曲/随机），到尾且非循环 → 停，
  播放器卡显示"播完了"。产品收益：iTunes 只给 30 秒试听，自动续播让歌单像电台一样流动，
  30 秒的尴尬消解大半。
- `media.control` 的 next/prev 落地为 `queue.next()/prev()`；`media.queue` 返回真队列。

### 2.3 历史与收藏

- **播放历史**：环形缓冲 50 条（曲目 + 时间），"再放刚才那首"用。
- **查询历史**：环形缓冲 20 条（天气/搜索的实体 + 结论摘要），供会话摘要注入。
- **收藏**：现有逻辑搬入域仓 + localStorage。`origin:'favorites'` 让"播放我的收藏"成队列。

### 2.4 长期记忆：显式记忆，不做自动学习

新 Tool 三件：`memory.remember` / `memory.forget` / `memory.list`（彩——用户口头指令即授权，
执行后复述确认）。存储 `{ text, createdAt }` 列表，**prompt 拼装时注入 system**：
"用户偏好：空调默认 24 度；出风别对着脸吹。"

**刻意不做的**：自动学习（"他连续三次调到 24 就记住"）与主动式触发（"等我降速你就开窗"）。
前者不可演示、不可解释；后者是另一个工程（条件监听 + 到点执行），仍留在已知待办。
划这条线的原因：**显式记忆是数据，自动学习是策略**——策略进代码就违反"不许意图分支"。

这解决 工程手册 已知待办里"长期记忆"的一半：Agent 从"这车不会记"变成
"记住了，以后都这样"。人设同步改口。

### 2.5 Agent 上下文注入的预算

注入总量控制在 ~300 token：状态段（现有）+ summary（现有）+ 会话摘要 ≤3 行 +
偏好 ≤10 条（超出取最近）。**注入的都是结论不是原始数据**——历史注入"最近放过：晴天、成都"
而不是 50 条记录，模型要细节走 Tool 查询。

## 3. Tools 维度

### 3.1 校验闸下沉：三条建卡路一个闸

现状：规则（orchestrator）、Tool（registry，有 checkSize+checkDataShape）、
handler（`desk.render` 直调，**什么都不过**）。空壳卡检查已经落在 desk（先例），
把尺寸与形状校验一并下沉：desk 构造时注入校验器（来自 config），
registry 保留"给模型的人话报错"。**每加一个 handler 不再是一个绕闸的机会。**

### 3.2 尺寸比对归一化

`checkSize` 现在是裸 `includes`——`'1/6'` 和 `'card'` 同档不同名，今天没炸只是拼写恰好一致
（这类坑已爆过一次：`LADDER.indexOf('1/3') = -1`）。比对前两侧过 `normalizeTier`。

### 3.3 canvas 尺寸白名单开全档

实测 bug：像素契约向模型承诺了 2/3（1638×1044）与 full 的画布，但模板没写 `sizes`
落到 COMMON_SIZES——模型按契约要 2/3 会被 `SIZE_NOT_SUPPORTED` 打回。
canvas/canvas-app 的 `sizes` 明确写十档全量。**合同和门卫必须说同一套话。**

### 3.4 ttl 补漏

天气卡还带着 `ttl:120`（上次清理只覆盖规则卡与能力目录，漏了 handler 建的卡）。
本次全量排查 handler 建卡：内容卡（天气）→ `untilDismissed`；
候选/问题卡（在等回应）→ 保留秒数。与 §4.3 家族机制同一提交——
单独改 ttl 会让多城市天气卡无限堆积。

## 4. HMI 维度

### 4.1 真相统一：形态函数搬 config

`src/screen/layout.ts` → `src/config/forms.ts`。**形态不是展示细节，是模型视角与像素视角
共享的契约**。desk.summary 改用 `formOf(template, dims).maxItems` 计算"还有 N 条"，
12 vs 4 这类分裂从结构上不可能再发生。

顺带得到反向映射 **suggestSize**：对同一张表反查——给定条数，取能装下它的最小档
（受模板 sizes 约束）。handler/规则不指定尺寸时采用。3 条候选不再占半屏，
12 条不再被截 4 条。

### 4.2 恢复通道 reconcile（对称性修复）

触发：`dismiss` / ttl 到期 / 覆盖层退出 → desk 内部"空间释放"事件。三步：

1. **规则卡补回**（立即）：orchestrator 订阅 desk 变化，规则 active 且 `findByKey` 缺席 → apply。
   修复 f(state) 不变量。补回失败（仍放不下）不重试，等下次变化。
2. **尺寸回落**（迟滞 2 秒，防抖动）：被仲裁压缩的卡回到 意愿（用户 resize 过）或
   建议（suggestSize/defaultSize）。`sizeLocked` 的卡不动——物理 > 意愿 > 建议链的自然推论。
3. **位置归位**（与 2 同批）：卡片记住上次坐标，tryPlace 先试记忆位，占不了才重排。
   布局对时间序列稳定，不再"一张卡进出、全桌重新发牌"。

恢复**静默进行**：挤出要告知（打扰了用户），恢复不播报（恢复不是打扰）。

### 4.3 卡片家族（同名实体的身份策略）

实测取证：天气 key 是 `weather:${adcode}`，为"周边哪个县最凉快"的**并行对比**特意设计
（真实 pilot 场景），但顺序单查（成都→北京）就成了堆卡。两个诉求同时满足：

- key 保留实体后缀；新增 `family: 'weather'`
- **批 = runtime 的调用轮次**：同一轮并行调用共批（五个县并存），新一轮的同族卡到达 →
  退掉不属于本批的旧卡（北京来了，成都退场）。不用时间窗魔数。
- 管道：runtime 每轮并行批递增 roundId → registry.invoke 透传 → handler 建卡时带上。
  规则卡无轮次概念，不参与家族。

### 4.4 渲染统一：mount / fill

9 个模板还是 `innerHTML` 整刷（19 处），触控一来滚动位置/按压态全丢——这是触控与
iframe 卡的共同前置。统一为 nav/player 已验证的模式：

```ts
mount(node, skeleton)   // 结构建一次
fill(node, data, form)  // 之后只填数据、切块显隐
```

### 4.5 生成式卡：动态尺寸 + 沙箱容器 + 流光边框

**动态 ≠ 任意像素**（会同时废掉死缝不变量、可预测性、像素契约）。动态 = 三层：

1. 全档位开放（§3.3）
2. **溢出自愈闭环**：车机屏量溢出 → `canvasNote` → director 机制升一档重排（≤2 次防振荡），
   降档同理（实测高度 < 60% 画布时缩一档）。`sizeLocked` 例外：用户缩小过的卡宁可折角提示。
3. suggestSize 兜底初值

**canvas-app（新模板，唯一的容器）**：

| | canvas（静态，现有） | canvas-app（可执行，新增） |
|---|---|---|
| 内容 | HTML/SVG + inline style | HTML + CSS + **JS** |
| 容器 | Shadow DOM + 消毒器 | `<iframe sandbox="allow-scripts">` + srcdoc |
| 隔离 | 样式隔离 | **源隔离**：拿不到 localStorage（Key 在里面！）、碰不到 bus |

安全三铁律（写进测试）：
① **绝不加 `allow-same-origin`**——属性字符串有断言锁；
② srcdoc 注入 `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'">`，模型代码不得外呼；
③ 纯文字兜底必填，代码跑挂不白屏。

**postMessage 桥**只认两个形状（不可信数据校验）：
`{type:'height', px}` → 喂溢出自愈；`{type:'action', value}` → 走"回答类"路由（§4.6）。

**流光边框两态**：进场/生成中 conic 渐变旋转 ≤2 秒 → 静置为渐变描边。
持续流动在驾驶环境是注意力噪音；"有事发生才动"沿用待选卡呼吸描边的先例。

### 4.6 触控（已拍板的三类路由 + 交互声明）

模板契约补第三件套（数据，不是代码）：

```ts
{ id: 'media', interactions: [
  { on: 'tap:next',   route: 'tool',   tool: 'media.control', args: { action: 'next' } },
  { on: 'tap:item',   route: 'answer' },              // 等价"第 N 个"，进对话
  { on: 'swipe:away', route: 'desk',   op: 'dismiss' },
]}
```

- **回答类** → bus 上行 `userAction` → director 合成用户输入进 Agent（"用户在屏上选了：XX"）。
  语音与触控可混用；序号圆点双重收益（语音对号 + 手指目标）。
- **操控类** → registry.invoke 直调，**不过模型**。对标方向盘硬按键 / MediaSession。
- **管理类** → desk 直调，记入意愿层（滑掉的卡规则不许下一秒刷回来）。

工程要求：pointer 坐标 ÷ stageScale（FLIP 踩过的同一个坑）；命中目标 ≥96px
（车规 15mm 折算），chip 整卡单目标；垂直滚动与横滑撤卡方向锁；
卡内滚动开放但 **"还有 N 条"保留给模型**（用户滚到哪儿模型不知道，模型世界观仍以 summary 为准）。

同步修订：`cursor:none` 移除；人设"不许让用户点"改为"可以说点一下也行"；
pilot「让用户点屏幕」硬伤反转；工程手册「明确不做」删触控条目。

### 4.7 数据更新可视化 + 小收敛

- **diff 高亮**：同 key 更新时变化字段闪一下（`hot` 机制从"哪扇窗被碰过"推广到"哪个字段变了"）
- truncate（截断三连归一）· esc（4 份并 1）· 屏幕几何常量从 grid.ts 注入 CSS 变量
  （复用 injectTokens 模式，消灭双写）· channelOf 接线（判据表从死代码变成真分派点）

## 5. Agent 维度（它的世界因此变大了什么）

**看见的更多**：summary（几何 + 截断 + 家族实体标注"这张天气是成都的"）+
会话摘要（最近发生）+ 偏好注入。**手更多**：记忆三个新 Tool + 队列相关既有 Tool（control 的 next/prev、queue）从残端变为真语义。
**打扰更少**：续播、恢复、操控触控都不过它。

**机制侵蚀防线**（写给未来的自己）：以下永远不进模型——
自动续播（无理解成分）、reconcile（纯几何）、操控类直调（延迟不可接受）。
判据始终是：这件事有没有"理解"的成分。

## 6. 判断记录

1. **域仓不进信号 store**——store 对齐 VSS，域数据不需要也不应该对齐 VSS。
2. **显式记忆，不做自动学习**——显式记忆是数据，自动学习是策略；策略进代码违反"不许意图分支"。
3. **家族批号用轮次不用时间窗**——时间窗是魔数，轮次是真实边界（同一轮 = 同一个意图的并行展开）。
4. **恢复静默**——挤出打扰了用户所以要告知；恢复不是打扰。
5. **iframe 绝不 allow-same-origin**——加了它 sandbox 等于没开，OpenRouter/高德 Key 直接暴露。
6. **触控三类路由在模板契约里声明**——模型学一个接口，不是 N 张卡 N 套协议。
7. **"还有 N 条"在可滚动之后依然保留**——模型的世界观以 summary 为准，滚动位置是它看不见的。
