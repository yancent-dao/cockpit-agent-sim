# Agent 过滤器架构：小模型先斩，大模型后奏（v2，产品定稿方向）

> 2026-08-12。触发：五条产品诉求——①全量 Tools 上下文过长响应慢；②车控/天气要亚秒级；
> ③一句话多意图要并行；④要不要 Skill 机制；⑤轮数增多不能变慢，记忆要异步。
>
> v1 曾设计"三层通道"（L0 反射缓存 / L1 调度 / L2 分域 worker fan-out），产品裁定过于
> 复杂。v2 按产品提出的**过滤器机制**重写：v1 的调度层要先"决策"再执行，决策本身占一轮；
> 过滤器是**边执行边转交**——小模型不当裁判直接干活。本文即定稿方向。

## 0. 现状瓶颈（实测链路）

`src/agent/runtime.ts` 单层循环：每轮 **55 个工具 schema（约 8k token）+ 全量车辆状态
（50 行）+ 无上限完整历史**，串行最多 6 轮，一个模型包打天下。

| 瓶颈 | 根因 | 后果 |
|---|---|---|
| 上下文肥大 | 55 schemas 每轮全量 | 首字延迟线性涨；>30-50 工具后选错率上升（Anthropic 官方结论） |
| 简单指令走全链路 | "开窗"和"规划带娃路线"同一条路 | 车控 1.5-3s |
| history 无上限 | 从不压缩 | 越聊越慢 |
| system 状态混在中间 | 车辆状态在 persona 后 | provider prompt cache 永不命中 |

## 1. 市场调研结论（2026-08，v1 留存）

- **Anthropic Tool Search**（2025-11 beta）：官方认定全量塞工具是反模式，按需发现省
  85% token；**>30-50 个工具精度下降**是官方结论。OpenRouter 用不到该 beta，思想自建。
- **量产车双系统是共识**：理想"快慢思考"、华为 MoLA 2.0、小鹏"25 秒十连指令"、
  小米 0.3s 冷启动——简单走快通道、复杂走慢通道是入场券。
- **记忆生产主流**：最近 K 轮全文 + 摘要前缀，异步压缩（MemGPT/Letta 一脉）。
- **Claude Skills**（2025-10）：渐进披露——目录行常驻、正文命中才注入。
- 投机执行+校验（speculative execution & verify）在推理系统（draft model + verifier）
  是成熟范式，过滤器机制是它在 Agent 层的对应物。

## 2. 过滤器架构（产品思路，定稿）

```
用户一句话
   │
   ▼
┌─ 快层：小模型过滤器（$0.1/M 档，上下文 <1.5k token）──────────┐
│ 工具面 = 仅「彩」权限的简单工具（车控/天气/媒体控制，见 §3）    │
│ 能做的立刻做（一轮内并行 tool calls）→ 话术立刻出 TTS          │
│ 做不了的一个不碰，不解释不道歉                                  │
└──────────────┬────────────────────────────────────────────────┘
               │ 转交报告（无论快层做没做事，一律转交）
               │   · 用户原话
               │   · 快层执行清单：每笔调用 + 参数 + 返回状态（含约束拒绝）
               │   · 快层已说出口的话术
               │   · 候选工具（快层对着工具目录顺手勾的，供慢层预载 schema）
               ▼
┌─ 慢层：大模型（后台跑，用户不等它）───────────────────────────┐
│ 职责一：执行剩余复杂任务（导航/多步/需确认的灰权限操作）        │
│ 职责二：校验快层干的活——错了就纠正并补一句话                   │
│ 职责三：判断要不要开口。快层已答对且无剩余任务 → 静默           │
│ 职责四：重活拆分——调 task.delegate 把独立子任务甩给子 Agent    │
│         并行跑（见 §6），自己只管发包、汇总、定展示             │
│ 工具面 = 目录全量一行速览 + 候选工具全 schema 预载              │
│          + tools.load 元工具随用随取（见 §5）                   │
└──────────────┬────────────────────────────────────────────────┘
               │ task.delegate × N（一轮里并行发起）
               ▼
┌─ 子 Agent 层（通用 runtime 复用，并行 N 个）───────────────────┐
│ 每个子 Agent：自己的 history + 按域装载的工具面 + 自己的轮次    │
│ 同步模式：主 Agent 等结果自己汇总                               │
│ 后台模式：主 Agent 先答"我去查着"，子 Agent 完成后出卡+播报通知 │
└────────────────────────────────────────────────────────────────┘
```

**关键体验**：用户听到的第一声永远是快层的（亚秒），慢层是背后的把关人和重活承担者。
纯简单指令：快层 <1s answered，慢层静默校验。纯复杂指令：快层空转交（+~300ms），
慢层照旧。混合多意图：简单部分立刻生效出声，复杂部分随后跟上——天然并行。

### 与硬约束对账

- **不许意图分支**：快慢分工不靠代码判断意图——快层"能做什么"由**工具面**（数据）圈定，
  它对圈外的事无能为力，自然转交。代码里零关键词、零意图枚举。
- **平台不认识具体 Agent**：快慢两层各一份 manifest（同一形状），编排器通用。
- **加能力 = 加数据**：新工具按权限自动落进快层工具面、按 `brief` 自动进工具目录，
  慢层随即可选可载。全链路没有任何一处要为新能力改代码。
- **黑/灰/彩复用**：快层只挂彩（错了纠正代价低、可逆）；灰（需确认）与多步任务
  天然只在慢层——**先斩后奏的风险边界正好是既有权限分级**，不新发明概念。

### Agent 公理修订

原："代码只做四件事：上下文拼装、并行调用、结果回填、确认流转"。
修订：**编排的"结构"进代码（快慢两段、转交报告、异步压缩是机制），编排的"决策"留在
模型**（做不做、对不对、要不要开口）。判据不变：代码出现意图字符串比对即违规。

## 3. 快层工具面：声明式圈定（不是路由）

工具定义新增数据位 `fast: true`——**显式标记，不做推导**：彩权限里也有不适合快层的
（music.play 是彩，但要搜索挑结果；memory 是彩，但要翻记忆），"简单"没有可靠的
推导规则，就老实标数据：

- 进快层：`window/climate/seat/steeringWheel/sunroof/wiper/ambientLight/fragrance/
  light/driveSetting/childLock` 的 set 类、`weather.query`、`media.control/volume/mode`、
  `vehicle.getState`
- 不进快层：导航全家（多步）、music/radio/news/video 的搜索播放（要挑结果）、
  灰权限（door/trunk/chargePort——需确认流）、memory、card、web
- 快层 system：微 persona（≤6 行，从主 persona 提取话术纪律）+ 车辆状态按其工具面的
  声明信号（writes/requires，registry 里现成的数据）裁剪（~12 行）+ 工具目录（供勾选
  候选转交，见 §5）+ 最近 2 轮。**不注入桌面摘要、偏好全文**——要用这些信息的活轮不到它。

快层约 18 个工具、schema ~2k token、TTFT 最快档模型 → 单轮 300-700ms 含话术。
快层模型在控制面板单独可选（默认取"快速模型"筛选里最便宜档），与慢层模型独立。

### 3.1 快层输出协议

一轮里快层要同时承载三件事，全部走标准 function calling，不发明新格式：

- **执行** = tool_calls（并行多笔）；
- **话术** = assistant text。纪律（persona 定）：自己执行了动作才报结果；一件没执行
  且目录里看得出这活有工具能干 → 只说一句极短承接（"我看看"/"稍等"）——
  **即时承接归快层**，不然纯复杂指令用户说完话要对着空气等 2-4 秒；纯闲聊快层直接答；
- **勾选** = 末尾调一次元工具 `handoff({ suggestedTools?: string[] })`（可选，不调
  也照常转交，慢层靠目录自载）。handoff 是 no-op 工具，只为把勾选装进标准协议。

### 3.2 快层上下文裁剪

"最近 2 轮"只取**用户原话 + 双层最终话术**，工具调用与结果一律不带——上一轮慢层
出过一份调研报告的话，原样带上快层就爆预算。它要的是对话承接感，不是执行细节。

## 4. 转交报告与校验（机制）

- 转交是**结构化数据进慢层 history**：快层的 assistant 消息（tool_calls）+ tool 结果原样
  拼入，慢层看到的是"同事已经做了这些"，不是转述——单一 history，两层共写。
- 慢层 persona 增加一段固定职责描述（校验/接力/静默判断），其余不变。
- 慢层"不需要回复"= 返回空话术且无新 tool call → runtime 不发 speaking 事件。
  纠错场景：慢层直接调工具改正 + 说一句（"温度我给你调回 24 了"）。
- 约束引擎、MRTR 确认流、不变量：两层共用同一 registry，**机制层一行不改**。
  快层被约束拒绝（如行驶中开门）也如实进报告，慢层负责解释或走确认流。

### 4.1 打断与轮次并发（barge-in）

快层答完、慢层还在跑时用户说了下一句——语音交互的常态，必须有并发模型：

- **turn 世代戳**：每个用户输入领一个递增 generation。慢层/子 Agent 的所有回填
  都带着自己的 generation。
- **过期慢层降级**：新 turn 开始时，旧 generation 的慢层**活照干完**（写信号、建卡
  照常——工作成果不作废），但**话术权收回**：正确性校验通过 → 彻底静默；
  发现快层做错了 → 不抢麦，改完走横幅（"刚才的温度帮你纠正到 24 度"）——
  横幅本来就是"对动作的解释"通道，正好。
- **history 串行化**：回填按 generation 排队追加，旧 generation 的回填插在新 turn
  的用户输入**之前**——时间线永远是"上一件事的结果 → 新的话"，不交错。
- 快层永不并发：新输入来时上一个快层若还没返回（罕见，它只有几百 ms），
  直接 abort 重来——用户重新开口就是最新意图。

### 4.2 确认流跨层：pending 确认直达慢层

灰权限确认由慢层发起后，用户的下一句（"确认"/"算了"）**不过快层**——快层不知道
有 pending 确认，接了必错。机制：registry 的 MRTR pending 态本来就存在，
runtime 检查"有 pending 确认"时新输入直达慢层。这是**状态分支不是意图分支**
（跟"屏幕上有候选卡就不再建卡"同类判据——看系统状态，不看话的内容）。
确认超时/用户转移话题由慢层按既有 MRTR 规则处理。

## 5. 慢层工具面：工具粒度按需装载（无"域"概念）

> 产品裁定：不引入"域"这一层分类学。每个 Tool 正交、自成最小单元，
> Agent 要做的只是**选工具**。这也正是 Anthropic Tool Search 的原始形态
> （defer_loading + 按需发现是工具粒度的，没有 domain taxonomy）。

- **工具目录**：每个 Tool 新增数据位 `brief`（≤20 字一行速览，如
  `navigation.search: 搜地点出候选`）。55 个 Tool 的目录 ≈ 800 token，
  代替 8k token 的全量 schema 常驻慢层 system。目录由 TOOLS 配置自动生成，不手维护。
- **预载**：快层转交报告带 `suggestedTools: string[]`（它对着目录顺手勾的候选），
  这些工具的**全 schema** 直接进慢层第一轮——大多数任务一轮就能开调，不多付延迟。
- **补载**：慢层挂元工具 `tools.load({ names })`——发现目录里有需要但没预载的，
  点名即取，下一轮 schema 就位。代价是偶尔 +1 轮，换来上下文永远 ≈ 目录 + 少数 schema。
- **常驻**：voice/card/memory/vehicle.getState + tools.load 全 schema 常驻（高频+元工具）。
- 快层勾不出候选（纯闲聊/不确定）→ 慢层第一轮只有目录+常驻，靠 tools.load 自取。
  没有"全量兜底"——目录+补载已保证可达性，全量反而回到老路。
- `CAPABILITY_DOMAINS` 退回本职：只服务能力目录卡的**展示**，Agent 链路不再引用。
- trace 记录预载/补载决策，pilot 统计补载率（补载率高 = 快层勾选质量差或 brief 写得含糊）。

## 6. 子 Agent 委托：task.delegate（慢层的并行执行）

产品用例："调研多个网站看今天石油行情，同时搜周杰伦的新闻生成报告"——两个独立重活，
串行要 20s+，必须并行，而且**拆分决策属于模型**：

- 慢层挂一个工具 `task.delegate({ goal, tools?, background? })`——tools 是主模型从
  目录里给子 Agent 点的装备（不点则子 Agent 同样走目录+补载）。它在**一轮里连发 N 个**
  delegate 调用——现有 runtime 的并行 tool calls（Promise.all）天然并行执行，零新机制。
- 每个子 Agent = 复用同一个 runtime 起一个独立 run：自己的 history（只带 goal，不背主
  对话包袱）、点名预载的工具面、自己的 maxRounds。返回结构化结果：
  `{ summary 话术, findings, cards?（要展示什么由它自己建） }`。
- **同步模式**（默认）：主 Agent 等全部结果回填，自己汇总话术 + 定展示——跨任务综合
  （"油价和新闻放一张摘要卡"）只有它有全局视角。
- **后台模式**（background: true，模型自己判断"这活得跑一会儿"）：delegate 立即返回
  taskId，主 Agent 先答"我去查着，好了叫你"；子 Agent 完成后**机械交付**——它自己产出的
  卡片上屏 + summary 走语音播报 + 横幅提示。交付不再叫醒主模型（公理 4：子 Agent 已经
  做完了全部理解工作，交付无理解成分）。若语音正忙（用户在对话中），通知排队等 idle。
- 边界：递归深度 1（子 Agent 不许再 delegate）；并发上限 3；子 Agent 无灰权限工具
  （需确认的操作必须回主对话走 MRTR，后台任务不许自己弹确认）；trace 全记录进检查器。

### 6.1 后台任务的 UI 呈现（产品点名）

- **状态栏任务指示器**：车机屏顶部状态栏（电量旁）新增任务芯片——转圈环 + 计数
  （"⟳ 2"）。有后台任务就在，没有就消失。这是第四类显示面：**持续状态**——
  不是内容（卡片）、不是一次性解释（横幅）、不是告警（覆盖层），所以进状态栏。
  数据流：director 任务池 → state 消息带 `tasks:[{id,label,status}]` → 屏端纯渲染。
- **运行中不占桌面格**：后台任务可能跑几分钟，挂一张"进行中"卡占 1/6 屏是浪费——
  感知由指示器承担，桌面留给内容。点任务芯片→ 出任务列表卡（机制直调，list 模板，
  不叫醒模型；再点可取消——实现走 fetch AbortController，子 Agent 当轮中断，
  已产生的副作用不回滚但记 trace）。
- **avatar 状态机**：快层话术走 speaking → 若慢层将接力则回 executing 微光
  （表示"还在办"），慢层定案后才 idle；慢层静默场景 3 秒后直接 idle。
  两层各说各话时 avatar 不许闪跳。
- **失败也要体现**：任务失败芯片变警示色 + 横幅一条（"股价调研没查成：来源打不开"），
  绝不静默蒸发——与"挤出必须告知"同一条纪律。
- **交付用生成式卡（canvas）**：股价分析、市场调研报告这类**个性化界面**正是 canvas
  模板的主场——子 Agent 直出 HTML/SVG（折线图、排版报告），走既有三道闸
  （消毒白名单 / 像素契约 / text 兜底），Shadow DOM 渲染。工具 brief 教子 Agent：
  "报告图表类结果用 canvas，列表类仍用 list，能用 list 表达的别用 canvas"。
  完成交付 = canvas 卡上屏 + summary 播报 + 芯片计数减一。

### 6.2 长时任务进展流（2026-08-13 产品提出：Claude 式"正在做什么"）

**原理：进展流是机制的副产品，零模型成本。** pipeline 每轮 LLM、每笔工具调用
本来就在发事件；每个工具的 brief 就是人话（"联网搜索现查""建卡片上屏"）——
进展行 = 「正在 + brief」，LLM 轮间隙 = 「在撰写内容（第 N 轮）」。
不新增任何数据表，不需要模型自报（自报要占轮次和 token，违背"快"）。

**双层呈现**（轻重分离，沿用"运行中不占桌面格"的裁定并对它做一次受控放宽）：

- **轻·常态**：状态栏任务芯片旁跟一行**当前动作**微字（"⟳ 1 · 正在联网搜索现查"），
  换动作时淡入换字。存在感 + 大致在干嘛，一眼可知，不占桌面。
- **重·按需**：点任务芯片 → 出**任务进展卡**（复用 list 模板，items = 步骤流）：
  「✓ 已装载工具 · ✓ 联网搜索现查（21s） · ⟳ 在撰写内容（第 5 轮）…」
  ——完成步骤打勾带耗时、当前步骤转圈，Claude 的活动流长什么样它就长什么样。
  live 更新（desk.render 同 key 刷数据，diff 高亮机制现成）；任务完成时
  进展卡自动撤、交付卡上屏（"这件事翻篇"撤卡语义）。

**机制改动清单**（无新模板、无新数据表）：
1. pipeline：subRun 的每轮/每调用 emit `taskProgress {taskId, label, kind, ms?}`，
   director 每任务维护步骤数组；
2. state 消息 tasks[] 增 `current: string`（芯片旁微字）；
3. taskChip 点开的任务列表卡升级为进展卡（items = 步骤流，仍是 list 模板）；
4. 完成/失败/取消时进展卡按"翻篇"撤。

边界：主对话（非后台）的进行中状态仍由 avatar 承担（thinking/executing 已有），
不出进展卡——它几秒就完，出卡反而闪。

与 v1 的区别：v1 是**代码+调度模型替主模型拆意图**再 fan-out（拆分决策被搬出了执行者），
这里是**主模型自己决定**拆不拆、拆几个、等不等——机制（并行、后台、通知）在代码，
决策全在模型，与公理修订完全一致。

## 7. 记忆系统总设计

### 7.1 范围：五类记忆

| 类 | 内容 | 存哪 | 生命周期 |
|---|---|---|---|
| ①状态（瞬时） | 车辆信号（VSS store） | 内存 | 会话内，不落盘 |
| ②会话 | 对话 epoch 摘要 + 最近 K 轮全文 + 域仓最近结论 | 内存；摘要另落一份"上回说到" | 会话内；摘要跨会话留一条 |
| ③领域 | 播放队列/播放历史/收藏/常用地址/（补）导航去过的地方 | localStorage 分域仓 | 跨会话；队列**刻意不落盘**（既有决策） |
| ④长期语义 | 用户明说要记的偏好与事实（memory.remember） | localStorage | 永久，直到 memory.forget |
| ⑤前瞻 | "等我停稳了叫我开窗"类触发器（待办已规划：规则引擎形状） | localStorage | 触发即焚或用户撤销 |

**自动学习仍明确不做**（"连续三次调 24 就记住"是策略进代码，违反不许意图分支）——
④只进显式记忆。①的注入按已装载工具的 writes/requires 裁剪（§5），不在本节展开。

### 7.2 什么时候召回：三条通道，判断权各归其位

- **常驻注入（无需判断）**：小而高频的记忆每轮自动进慢层 system——偏好 ≤10 条、
  域仓最近结论 ≤3 行、**记忆目录 1 行**（"收藏 12 首 · 常用地址 3 个 · 去过 8 地 ·
  记住的事 5 条"）。目录是关键：**模型不知道自己不知道**，没有目录它永远想不起来查——
  这跟工具装载是同一个问题的同一个解（目录常驻 → 按需取详），两处同构。
- **模型主动召回（工具）**：用户话里指涉过去（"上次那家店""我常去的""放我收藏的"）→
  模型自己调 memory.search / places.list / media.favorites / history 类工具取详情。
  **何时召回、召回什么的判断 100% 在模型**——persona 和工具 brief 教它什么时候该查，
  代码零关键词。快层不挂任何记忆工具：要翻记忆的活天然轮不到它。
- **机制自动（零模型）**：续播读队列、规则卡读域仓、前瞻触发器到点执行——
  无理解成分的事不叫醒模型（公理 4）。

### 7.3 召回哪些：注入封顶，检索给 query

- 注入层定量封顶（10 条 / 3 行 / 1 行），挤不进的靠工具召回——system 的每个字都在挤别的。
- 检索是 `memory.search({ query })`：模型给自然语言 query，机制做关键词/子串匹配
  返回 top-N。**不做 embeddings**（OpenRouter 无端点，Demo 规模关键词足够；
  相关性不好先改存储时的措辞——存"喜欢 24 度"而不是原话逐字，检索友好是写入方的责任）。
- 摘要压缩时**保留检索线索**：epoch 摘要不只写结论，同时把被折叠轮次里的实体
  （地名/人名/歌名）列成一行——摘要是索引不是墓志铭，用户说"刚才那个加油站"时
  模型在摘要里找得到锚点。

### 7.4 怎么落盘：全部 localStorage 分命名空间（零后端不动摇）

- 写入时机三类：**用户明说**（memory.remember，工具写）· **机制随事件写**
  （播了就进历史、导航到了就进去过、收藏就收藏）· **异步压缩写**（对话摘要，见 7.5）。
- 对话**逐字稿不落盘**：占地方、翻旧账没场景、还有隐私包袱——只落摘要。
- 落盘失败（localStorage 满/禁用）降级为内存态，功能不断，重启即失——宁丢勿崩。

### 7.5 异步压缩（响应路径零占用）

```
history = [ epoch 摘要（≤10 行，含实体索引行）] + [ 最近 K=4 轮全文 ]
```

- 慢层回合结束（用户已听到全部答案）后 fire-and-forget：小模型把溢出轮次折叠进摘要，
  顺手更新"上回说到"落盘。失败保持原样下轮重试；压缩中来新 turn 则放弃本次。
- 下次会话启动，"上回说到"作为一行注入——"接着昨天那个路线"接得上。
- 效果：上下文与轮数解耦，第 100 轮与第 5 轮一样快。

## 8. Provider 层加速（白捡项）

- system 重排：稳定前缀（persona+工具目录）在前，易变内容（车辆状态/桌面）挪尾部，
  OpenRouter 透传的 prompt cache 才能命中。
- 车辆状态按已装载工具的 writes/requires 声明裁剪（registry 现成数据）：50 行 → ~12 行。
- streaming：`llm.chat` 流式 + 车机屏逐字播报（工程项，P2）。

## 9. Skill 机制（P2，慢层与子 Agent）

### 9.1 用处：过程性知识的第三个家

Skill 回答"**怎么把一串工具用出章法**"——这类知识今天只有两个去处，都是错的：
塞 persona（常驻膨胀，每轮付费，且 22 行纪律会被稀释）或塞 tool desc（工具描述变小作文，
跑批教训№1：desc 和人设打架时模型两边都不对）。Skill 是第三个位置：**按需注入的剧本**。

四个概念的分界：**Tool = 能力（能做什么）· Skill = 方法论（怎么做好，作者写的静态知识）·
persona = 品格（永远成立的纪律）· 记忆 = 事实（用户与世界的状态，运行时写入）**。
"以后导航避开高速"是偏好进记忆；"顺路充电该先看续航再比绕路"是章法进 Skill——
用户改不了 Skill，模型改不了 persona，两个方向都不许串。

例：顺路充电 skill = 查续航 → searchAlong → 按绕路距离/桩功率排序 → 低续航直接设途经点、
充裕则出候选卡问 → 话术必报"绕路几分钟"。五步章法跨四个工具，哪个单独的 desc 都装不下。

### 9.2 启用与召回：与工具/记忆第三次同构

- **目录常驻**：每个 skill 的 `name + whenToUse`（≤20 字）拼一行进慢层 system。
- **模型点名**：慢层挂元工具 `skill.use({ name })`——它判断"这活有剧本"就调，
  正文（≤40 行）作为 tool result 进 history，随附 `tools` 字段顺带解锁额外工具
  （走 tools.load 同一通道）。下一轮照剧本干活。
- **判断 100% 在模型**：命中率取决于 whenToUse 文案（数据）。代码不做任何
  "这句话像不像顺路充电"的匹配——那是意图分支。pilot 统计 skill 命中/漏用率，
  低了改 whenToUse 措辞，改数据不改码。
- 这是目录→按需取详的**第三次复用**（工具 §5、记忆 §7.2、Skill §9）——
  三类上下文一个装载模式，模型学一次就会。

### 9.3 谁挂谁不挂

- 慢层挂全目录；**子 Agent 也挂**——"市场调研报告"skill（来源 ≥3、对比表、结论先行、
  canvas 排版骨架）正是给 delegate 的调研子 Agent 用的，报告质量从"随机发挥"变"有章法"。
- 快层永远不挂：要剧本的活轮不到它。
- 加 skill = `agents/main-agent/skills/<name>.ts` 加文件 + manifest 挂名，平台零改动。

**首批（产品定）：导航、媒体两个**——正好是工具最多、章法最重的两个板块：

- **导航 skill**：搜索→候选卡→设目的地→途经点→比路线的全流程章法；撤卡时机
  （候选卡按"翻篇"撤不按"开口"撤）；话术纪律（屏上有的别逐条念、必报绕路时长）；
  顺路充电作为其中一节（查续航→searchAlong→按绕路/功率排序）。
- **媒体 skill**：搜歌整批入队→续播→收藏的链路章法；CP 特性坑（iTunes 只有 30 秒
  试听、电台主域名不可用、NewsAPI 只在 localhost）——这些今天散在 tool desc 里
  把描述撑成小作文，正该搬进 skill。

后续候选：长途规划（途经点+沿途天气联查）· 接娃场景 · 市场调研报告（canvas 交付）。

## 10. 响应速度预算（验收线）

| 路径 | 现状 | 目标 |
|---|---|---|
| 简单车控/天气（快层直答） | 1.5-3s | **<1s**（含话术） |
| 混合多意图的简单部分 | 串行等全链 | <1s 先生效先出声 |
| 复杂任务（慢层） | 5-15s | 2-4s（schema 常驻 8k → 目录 0.8k + 预载少数） |
| 多个独立重活（调研/报告） | 串行累加 20s+ | delegate 并行 = 最慢分支；或后台跑完通知，主对话零阻塞 |
| 纯复杂指令的过滤器开销 | — | +300ms 上限（快层空转交一轮） |
| 第 50 轮对话 | 线性变慢 | 与第 5 轮持平 |

pilot 新增：分层计时落盘、快层误执行率（慢层纠正次数/快层执行次数）、
慢层静默率、工具补载率。RUBRIC 增"速度"维度。

## 11. 明确不做 / 远期

- **L0 反射缓存（<50ms 精确匹配）**：v1 遗产，按"过于复杂"裁掉。快层亚秒即产品底线；
  若未来实测不够快再回头看。
- **语义缓存**：OpenRouter 无 embeddings 端点，不为缓存引第二家 API。
- **端侧小模型**：零依赖 + Demo 定位，不做。
- **快慢层写冲突事务**：同信号并发写靠约束引擎+不变量兜底，实测出问题再议。
- **代码侧意图拆分**（v1 的调度层 fan-out）：不做。并行分身保留但换了主人——
  拆分决策归慢层模型（task.delegate，§6），代码只提供并行与通知机制。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 快层做错（开错窗、调错温） | 只挂彩权限（可逆低代价）；慢层每单必检，错了立刻改+补话术；pilot 统计误执行率，>3% 换快层模型 |
| 快层越权乱试 | 工具面物理隔离——圈外工具 schema 根本不在它上下文里，想调也调不了 |
| 两层话术打架（快层说完慢层又说） | 慢层看得到快层原话，persona 明确"别人说过的不复述"；静默是它的合法选项 |
| 快层慢层结论矛盾（天气查两遍不一致） | 快层查过的慢层不重查（报告里有结果）；persona 固定这条 |
| 慢层缺工具却不自知（brief 太含糊没勾中） | 目录常驻它随时看得见全集；pilot 盯补载率，高了改 brief 文案（改数据不改码） |
| 转交延迟拖累纯复杂指令 | 快层上下文压到 <1.5k token 上限 ~300ms；可接受 |
| 后台任务与新对话打架 | 通知排队等语音 idle；子 Agent 无灰权限，绝不后台弹确认 |
| 用户打断时慢层迟到话术插错话题 | turn 世代戳：旧 generation 活照干完但话术权收回，纠错走横幅（§4.1） |
| 确认流被快层截胡 | pending 确认态下新输入直达慢层——状态分支不是意图分支（§4.2） |
| 子 Agent 失控（递归/刷额度） | 深度 1、并发 ≤3、maxRounds 独立封顶；trace 全记录 |
| 成本翻倍 | 快层 $0.1/M 档单次 <0.01 分；慢层 schema 省 6.5k token/轮，净省 |

## 13. 实施分期（每期 TDD + pilot 跑批验收）

- **P1（架构主体）**：①快层过滤器（manifest + fast 标记 + handoff 协议 + 承接纪律）；
  ②工具目录（brief 数据位）+ 慢层预载/tools.load 补载 + 状态按 writes/requires 裁剪；
  ③turn 世代戳与 barge-in 降级 + pending 确认直达慢层（§4.1/4.2，**架构正确性
  的地基，不是附件**）；④异步记忆压缩；⑤system 重排缓存前缀；⑥快层模型面板可选。
- **P1.5**：⑦task.delegate 同步模式（并行子 Agent + 主模型汇总）；⑧后台模式
  （taskId + 完成机械交付 + 通知排队 + AbortController 取消）+ 状态栏任务芯片 +
  任务列表卡 + canvas 交付。
- **P2**：⑨Skill 机制 + 首批 2 个（导航、媒体，产品定）；⑩streaming；
  ⑪（视 pilot 数据）快层模型/工具面调优。
- 预算：`src/agent/` 500 → **800 行**（过滤器、转交、压缩三块机制进驻）。
  超了先查是不是策略漏进了代码。
