## S1 章法草稿(能力定义)

### 用户旅程章法(五步)

| 步 | 用户说 | 模型该干什么 | 屏上 | 嘴上(附一个问题) |
|---|---|---|---|---|
| 0 | "我要去云南旅行"(宽泛) | 给 2–4 条线路收敛 | 选线卡 | "雪山古城还是热带雨林?" |
| 1 | "大理丽江那条" | 查玩法,交按天草稿 | Day 动线列表+行前准备 | "几天假?"(有天数问"哪天出发") |
| 2 | "就 5 天" | 调整重交,细排全文 | 完整时间轴,上下滑 | 告知:"认可说'就按这个来'" |
| 3 | "就按这个来" | 建任务+配监控(接管) | 价格块置顶+天气进行程 | 告知:"盯上了,有变化叫你" |
| 4 | (到价) | 摆事实带依据 | 决策条置顶 | "比 30 天均价低 12%,定吗?" |

随意变动是常态:改某天=重交完整 days;换住宿段=撤旧盯新;
改日期目的地=update,监控天气自动重算。没有"锁定"状态。

### 能力清单

| 动词 | 它做什么 | 返回里必须有什么 |
|---|---|---|
| 交攻略(→travel.plan) | lines 或 days 进仓上卡 | 下一步指引(认可后 create) |
| 建任务(→travel.create) | 任务+监控一次配齐 | **首采参考价 quotes**、缺什么、空内容提醒 |
| 盯一项(→travel.watch) | 加监控/阈值 | **首采现价** |
| 撤一项(→travel.unwatch) | 停监控留样本 | 停了什么 |
| 查全景(→travel.list) | 问答数据底座 | 30 天事实(极值/分位/方向)、draft 指引、showTrend 钻取 |
| 现在什么价(→travel.refresh) | 立即采一轮 | **latest 每项最新值**——答案在返回里 |
| 改行程(→travel.update) | 改任务字段 | 新旧对照+受影响项+目的地变更指引 |
| 删任务(→travel.delete,灰) | 连监控一起删 | 停了哪些(要念出来) |

### 显示清单

| 屏显需求 | 落点 |
|---|---|
| 选线/草稿/全文/盯价/到价 | trip 卡(systemOnly,同 key 原地生长) |
| 价格走势钻取 | trend 卡(travel.list showTrend 才出) |
| 到价提醒(行驶中) | 横幅通道 + trip 决策条 |
| 委托回执 | 横幅(动作做完不占格子) |

### 边界清单

- 灰:travel.delete(删任务连监控)
- 黑:无(本域无安全件)
- 明确不做:下单/支付(Tool 契约里没有下单参数——边界落在机制上)、
  具体酒店选择(盯"段"不盯某家)、多任务并行卡(一张卡=最新一次旅行)
- whenToUse:出去玩/旅游攻略/机酒盯价/看行程(17 字)

## S2 落点清单

| 需求 | 落点 | 备注 |
|---|---|---|
| 采样节奏(机酒每时+上电,汇率每天) | 数据 | DEFAULT_RHYTHM 表,everyMs/onBoot 字段 |
| 采样调度 | 机制 core/monitor | lastAt 空=立刻到期(建完即采) |
| 趋势分析 | 机制 core/trend | **只摆事实不做推荐**,verdict 归模型 |
| 该不该买/怎么说 | 策略 skill | 建议必须带依据,band unknown 只报数 |
| trip 卡三档 | UI | 档位判据即滚动判据 |
| 每日天气 | 机制(自动) | 确认后拉,超窗存 null 不编造 |

数据源:

| 数据 | 源 | 取舍与调研结论 |
|---|---|---|
| 汇率 | frankfurter.dev | 零 Key、官方 CORS、自带 30 天真历史、per100 口径 |
| 机酒价 | travelMock | RapidAPI 调研结论:免费层+国内覆盖+历史价格**三者不可兼得**(候选 ntd119/Flights Scraper Sky 50 次/月、Agoda 500 次/月);mock 带"示例数据"标记+确定性种子+录制槽,Key 到位换一行 |
| 天气 | amap geocode + Open-Meteo daily | 16 天预报窗;高德 lng,lat 序 vs OM lat,lon 老坑;国内 amap 永远直连 |
| 攻略内容 | web.search(OpenRouter :online) | 模型组织成结构化 days |

## S4 域仓(src/state/travel.ts,localStorage)

```ts
TravelTask  { id,title,destination, departDate?,returnDate?,travelers?,
              status: draft|active|archived, days?,prep?,summary?,
              lines?,wx? }          // wx 与 days 对齐,窗外 null
TravelWatch { id,taskId, kind: flight|hotel|fx|news, label,
              threshold?,direction?,expiresAt?, status,
              everyMs?,onBoot?,lastValue?,lastAt?,
              stay?: {city,dayFrom,dayTo} }   // 分段住宿
TravelSample { watchId,at,value }   // 30 天滚动窗淘汰
```

- 进仓:任务/委托/样本/攻略/天气(都是跨上下电要活着的用户数据)
- 不进仓:趋势分析结果(现算)、播放型遥测(无)
- 配额风险:样本 30 天窗+prune 兜底;写静默失败已知

## S6 引擎

- `core/monitor`:due(items,now,boot),everyMs+onBoot 两个数据字段表达全部策略
- `createTravelEngine`:sampleDue 只采点名项(免费额度小),fired→trip
  决策条(不弹新卡);items() 喂调度器
- 天气 refreshWx:plan/create/update(日期或目的地变)触发,fire 在 handler 内

## S7 卡片

- **trip**(systemOnly,hall/court/stage,默认 court):
  blocks 基础 [hero,days,prices],court +[herofull,prep,dayfull,decide],
  stage 再 +daycols——块只增不减。
  阶段=数据形状:lines→选线;days→全文;flight/stays→盯价(置顶);
  decide→到价(价格块与全文之间)。
  自带滚动容器 tppage(.bd flex-end 坑);hall 单行摘要不滚;
  每天行头带 wx(null 缺席);换城日琥珀;住宿分段各带 mini 走势。
- **trend**(钻取):现价+曲线+提醒线+分位,verdict 模型给
- 已退役:guide/itinerary(并入 trip)、轮播机制(tpf* keyframes)
