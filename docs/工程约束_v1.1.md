# v1.1 · 工程约束与技术选型

> 本文是 v1.0 需求规格说明书的补充，不改动需求，只约束实现方式。
> 触发本文的三条确认：① 基准屏 2560×1440 确定 ② 不在鸿蒙体系内，自建成立 ③ **底层代码必须保持简洁**
> 日期：2026-08-10

---

## 0. 先把"简洁"翻译成可执行的东西

"保持简洁"如果只是原则，三个月后一定会被违反。所以本文把它拆成四条可检查的约束：

| # | 约束 | 检查方式 |
|---|---|---|
| 1 | **零后端** | 产物是一组静态文件，双击即可打开 |
| 2 | **加能力 = 加数据，不加代码** | 新增一个信号 / 约束 / Tool，若需要改 core 代码即视为设计失败 |
| 3 | **复杂度只允许落在三个已知位置**，且各有上限 | 见 §3 |
| 4 | **代码里不允许出现意图分支** | 出现 `if (intent === ...)` / `if (userSaid.includes(...))` 即违规 |

第 4 条是 v1.0 第一原则「Tools=机制 / Agent=策略」的可执行版本。它是这套系统会不会腐烂的分水岭——一旦代码开始猜用户想干什么，分层就名存实亡了。

## 1. 技术选型

### 1.1 决策与理由

| 项 | 决策 | 理由 |
|---|---|---|
| 后端 | **无** | Demo 场景不需要。LLM API 从前端直连，Key 存本地配置文件（不入库、不提交） |
| 构建 | **Vite** | 零配置、启动快、原生支持 TS |
| 框架 | **Vue 3 SFC**（备选 React） | 卡片系统需要动态布局与列表 diff，裸 DOM 会很痛苦；Vue SFC 的心智负担低于 hooks。**若团队更熟 React 就用 React**，这条不重要 |
| 语言 | **TypeScript** | 接口契约是本项目的核心产物，类型能防止契约漂移。Vite 下零额外配置，不增加复杂度 |
| 状态管理 | **不引入任何库** | State Store 本身就是状态管理，再套 Pinia/Redux 是重复 |
| 样式 | **原生 CSS + CSS 变量** | Design Token 就是 CSS 变量，不需要 Tailwind |
| 存储 | **内存 + 可选 JSON 导入导出** | 不用数据库，不用 localStorage |
| 测试 | **Vitest** | 只测 core 与 tools，UI 不做单测 |

### 1.2 依赖预算

**运行时依赖 ≤ 5 个。** 当前预计：`vue` · LLM SDK（或直接 fetch，可为 0）· 一个 YAML 解析器 · 一个轻量 schema 校验。

任何新增依赖需要回答一句话：**"不加它要多写多少行？"** 少于 200 行就自己写。

### 1.3 明确不引入（附理由）

| 不引入 | 理由 |
|---|---|
| **Eclipse autowrx（不 fork）** | React+TS+Vite+Tailwind + Node + MongoDB 全栈，架构围绕"浏览器跑 Python 脚本"，接 Agent 改动量大于自建，且 MongoDB 破坏零后端 |
| **Eclipse Kuksa databroker** | Rust + gRPC + Docker，对纯前端 Demo 是净负担 |
| Tailwind / UI 组件库 | 座舱视觉是定制的，组件库反而要覆盖 |
| 状态管理库 / 路由库 | 单页单屏，用不上 |
| 3D 引擎 | 车辆用 SVG 二维示意足够，且更清晰 |

### 1.4 「对齐而不引入」策略

不用它们的代码，但要用它们的**语义**——这样简洁性和可交接性能同时保住：

| 对象 | 引入形态 | 代价 |
|---|---|---|
| **VSS v6.0** | 只作为 `vssPath` 字段值 + 构建期校验 | 几乎为零 |
| **Kuksa** | State Store 的 `get / set / subscribe` **方法签名照抄它的语义** | 零。将来接真车换一个 adapter 即可 |
| **MCP MRTR** | 返回契约用 `inputRequired` 形态 | 零 |
| **AAOS** | 信号元数据三元组的字段名与取值 | 零 |
| **autowrx** | 只借鉴两点：VSS API 目录的组织方式、车模 widget 的映射思路 | 零，读文档不读代码 |

## 2. 数据驱动：加能力 = 加数据

这是简洁性最大的杠杆。**代码只写解释器，能力全部用数据描述。**

### 2.1 三份数据文件

```
config/
├── signals.yaml       # 信号定义
├── constraints.yaml   # 约束与联锁
├── tools.yaml         # Tool 定义
└── cards.yaml         # 卡片模板定义
```

**signals.yaml**

```yaml
- alias: cabin.window.driver.position
  vssPath: Vehicle.Cabin.Door.Row1.DriverSide.Window.Position
  type: number
  range: [0, 100]
  access: READ_WRITE
  changeMode: ONCHANGE
  transition: 4000        # ms，全行程；有此字段即自动获得过渡仿真
  permission: 彩
```

**constraints.yaml** —— 表达式**故意限定为三元组**，不支持嵌套逻辑：

```yaml
- id: SPEED_LIMITED
  when:   ["vehicle.speed", ">", 100]
  target: "cabin.window.*.position"
  action: clamp
  value:  30
  message: "当前车速 {vehicle.speed}km/h，车窗最多开到 {value}%"

- id: CHILD_LOCK_ON
  when:   ["cabin.childLock", "==", true]
  target: "cabin.window.rear*.position"
  action: reject
  message: "儿童锁已开启，后排车窗当前不可控制"
  suggestion: "可以先关闭儿童锁，或改开前排车窗"
```

> **取舍说明**：三元组覆盖约 90% 的约束场景，剩下 10% 用具名谓词函数（见 §3.1），**绝不引入表达式引擎或 `eval`**。这是保持简洁的关键取舍。

**tools.yaml** —— 纯 setter 类 Tool **零 handler 代码**：

```yaml
- name: window.set
  desc: 控制指定车窗的开度
  permission: 彩
  params:
    window:   { enum: [driver, passenger, rearLeft, rearRight, all] }
    position: { type: number, range: [0,100] }
  writes: "cabin.window.{window}.position"   # 有 writes 即自动生成 handler
```

只有真正有逻辑的 Tool（`navigation.search`、`card.show`）才需要写 handler。**预计 44 个 Tool 里约 25 个是零代码的。**

### 2.2 由数据自动派生的四样东西

一处定义，四处生成，这是不写重复代码的根源：

```
signals.yaml + tools.yaml
   ├─→ Tool Schema（OpenAI / Claude / MCP 三种格式）
   ├─→ 调试面板控件（控制面板里的滑条与开关自动长出来）
   ├─→ 能力目录卡内容（v1.0 §6.1 要求「不许手写页面」）
   └─→ 接口文档页（给研发的交付物）
```

## 3. 复杂度的三个落点与上限

复杂性不会消失，只会转移。与其让它到处渗，不如指定三个落点并各设上限：

### 3.1 约束引擎

| 项 | 约定 |
|---|---|
| 上限 | 只支持 `[path, op, value]` 三元组；op 限 `> < >= <= == !=` |
| 超出怎么办 | 写成一个**具名谓词函数**，登记在白名单里，在 yaml 里按名字引用 |
| 禁止 | `eval`、表达式解析库、嵌套 and/or |
| 预算 | **< 150 行** |

### 3.2 卡片布局

| 项 | 约定 |
|---|---|
| 上限 | 因为「每个尺寸只允许一种形状」，布局退化为**一维排布**，用贪心算法 |
| 原则 | **不追求最优解，追求可预测解。** 演示者能预判结果比空间利用率重要 |
| 满载策略 | 降尺寸 → LRU 挤出 → 告知用户（v1.0 §4.3 已锁定） |
| 预算 | **< 250 行** |

### 3.3 Agent 编排

| 项 | 约定 |
|---|---|
| 上限 | **全部在 Prompt 里，代码零意图分支** |
| 代码只做四件事 | 上下文拼装 · 并行调用 · 结果回填 · 确认流转 |
| 违规信号 | 代码里出现 `if (intent===...)`、关键词匹配、意图枚举 |
| 预算 | **< 400 行** |

> 第三条最容易被破坏。当 Agent 表现不好时，最大的诱惑就是"在代码里兜一下"。**兜了就等于把 Demo 的说服力抽掉了**——观众会分不清是模型聪明还是代码作弊。正确做法是改 Prompt 或改 Tool 描述。

## 4. 代码规模预算

| 模块 | 预算 | 说明 |
|---|---|---|
| `core/`（State Store + 事件 + 约束 + 过渡仿真） | **< 800 行** | 含 §3.1 的 150 行 |
| `tools/`（注册表 + 授权 + 返回契约 + 有逻辑的 handler） | **< 600 行** | 零代码 Tool 不计 |
| `cards/`（卡片系统 + 布局 + 生命周期） | **< 700 行** | 含 §3.2 的 250 行 |
| `agent/`（Runtime + 注入 + 编排 + MRTR） | **< 500 行** | 含 §3.3 的 400 行 |
| **核心合计** | **< 2600 行** | |
| `screen/` + `director/`（UI） | 不设硬预算 | UI 天然啰嗦，但必须无业务逻辑 |
| `config/*.yaml` | 不设上限 | 数据越多越好，这正是我们要的 |

**超预算的处理**：不是提高预算，而是检查是不是有逻辑漏进了不该在的地方——尤其检查 UI 里有没有藏业务规则。

## 5. 明确不做（简洁性靠"不做"保证）

| 不做 | 何时再议 |
|---|---|
| 后端服务、数据库、用户系统 | 永不 |
| 多屏（仪表 / HUD / 副驾 / 后排） | 第二块屏有真实需求时，届时抽 `ScreenProfile` |
| 日间模式 | v0.3 |
| 完整设计系统、表单体系、国际化 | 永不 |
| Tool 路由 / 分级检索 | 实测到模型选错或明显变慢时。**26 个 Tool 直接全量挂载** |
| 真实 ASR（用文本输入模拟） | v0.2 |
| 多 Agent 实现（只留接口） | 有第二个 Agent 的真实需求时 |
| 主动式触发 | v0.2 |
| CAN 时延 / 丢包 / 报文级仿真 | 永不（v1.0 §2.6 已定） |
| 接真车 / Kuksa / VISS | 有落地需求时，换 adapter |

## 6. 目录结构（扁平优先）

```
cockpit-sim/
├── config/
│   ├── signals.yaml
│   ├── constraints.yaml
│   ├── tools.yaml
│   └── cards.yaml
├── src/
│   ├── core/          # State Store · 事件总线 · 约束引擎 · 过渡仿真
│   ├── tools/         # 注册表 · 授权 · 返回契约 · handlers/
│   ├── cards/         # 卡片系统 · 布局 · 模板
│   ├── agent/         # Runtime · 注入 · 编排 · MRTR
│   ├── screen/        # 车机屏
│   └── director/      # 控制面板
├── agents/
│   ├── main-agent/    # manifest.yaml + prompt.md
│   └── demo-agent/    # 3 个 Tool，用于验证分层
├── tests/
│   ├── contracts/     # Tool 契约测试
│   └── golden/        # 13 条 Golden Case 回归
└── index.html
```

**不做 monorepo。** 单包单 `package.json`，`src/` 下按目录分层即可。monorepo 的收益要到多包复用时才出现，现在只会增加配置负担。

## 7. 三条会在实现期反复用到的判断准则

1. **要不要抽象？** —— 出现第二次重复才抽。第一次直接写。
2. **要不要配置项？** —— 演示时会当场改的才做成配置，否则写死。
3. **要不要兜底？** —— 兜到 Tool 层为止；Agent 表现不好改 Prompt，不改代码。
