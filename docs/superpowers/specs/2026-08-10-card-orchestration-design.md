# 卡片编排重设计:状态驱动 + 统一桌面

日期:2026-08-10 · 状态:已批准,执行中
取代需求规格说明书 v1.0 §4.3(分区)、§4.4(卡片分类)的部分内容,§4 其余保留。

## 起因

导航场景暴露三个结构性问题:
1. "该显示什么"全压在模型自觉上——模型忘调 `card.show`、搬错 data,卡片就空白/缺图,只能靠层层校验兜
2. 卡片内容没有自刷新源头——ETA 变了卡片不动,除非模型再手动搬一次
3. 状态→卡片映射无全局设计,同一场景两次演示长得不一样,违背"可预测优先于最优"

## 决策(已与产品确认)

1. **系统自动驱动为主,Agent 只管临场内容**。状态→卡片映射做成声明式规则,模型不再为基础展示搬数据
2. **布局仲裁用规则算法,不动用模型**
3. **导航中导航卡占左 2/3(2×2),不可被挤,导航结束自动消失**
4. **删除固定区/Agent 区双区模型**,桌面统一 6 格
5. **暂不做常驻卡**,所有卡片按需出现、按需退场,默认桌面为空;`desktop.pin`/`unpin` 移除(配置注释保留)

## 桌面模型

3列×2行=6格,统一画布。形状体系(每尺寸唯一形状):

| 尺寸 | 占格 | 形状 |
|---|---|---|
| 1/6 | 1 | 1×1 |
| 1/3 | 2 | 横向 1×2 |
| 1/2 | 3 | 整行 1×3 |
| **2/3(新增)** | 4 | **左锚定 2×2,唯一合法位置是左两列** |
| full | 6 | 整屏覆盖,退出还原(机制沿用) |

有 2/3 卡时剩余空间为右列上下两个 1×1,只容 1/6 卡。

卡片来源两类:
- **规则卡**:状态自动驱动,条件消失自动退场,模型不参与
- **临场卡**:Agent 因一次意图创建,必须带 ttl

## 规则引擎(src/config/cardRules.ts,纯数据)

两种规则:
- **状态卡规则**:`when`(三元组数组,与关系)成立期间卡片必须在场;`watch` 的信号变化触发 data 重建(自刷新);条件破灭自动退场
- **事件卡规则**:无 `when`,`watch` 的信号一变即确保卡片在场,带 ttl 自动过期

data 用具名 builder 白名单(沿用具名谓词先例),编排器创建时注入依赖(store/amap)。`navigation.nextInstruction` 升级为信号,builder 全部从信号取数。

v0.1 规则清单:
- `nav-active`(状态卡):navigation.active==true → nav 卡 2/3,priority 3,evictable:false,watch eta/distance/location
- `window-feedback`(事件卡):cabin.window.*.position 变化 → control 卡 1/6,ttl 30

## 编排器(src/cards/orchestrator.ts,~120 行)

订阅 Store→评估规则→通过与 Agent 相同的 desk API 建/更/撤卡。同一布局仲裁,不开后门。

## 布局仲裁(desk.ts 升级)

- 放置顺序:priority 降序,同级 createdAt 升序;行优先从左到右放第一个合法位置
- 空间不够:低优先级 evictable 卡先阶梯降尺寸,降无可降 LRU 挤出,必须告知(note 机制保留)
- `evictable:false` 永不被挤
- 优先级:system(4) > 规则卡(3) > 临场任务卡(2)
- 位置由 desk 统一计算,bus 下发 {row,col,rowSpan,colSpan},车机屏不再自行排布

## Tools 变化

- 移除 `desktop.pin`/`desktop.unpin`
- `desktop.getLayout` 返回简化:单列表+剩余格数
- `nav` 模板尺寸只剩 2/3,desc 注明"系统自动管理,勿手动创建"

## 补充(同日实施):查询/交互结果也自动上屏

在规则卡(状态驱动)之外,第二类自动显示——Tool 层在返回结果的同时直接上屏,模型零参与:

| 触发 | 卡片 | 撤场 |
|---|---|---|
| `navigation.search` 多候选 | list 候选卡 1/2 | `setDestination` 成功即撤 |
| `weather.query` 成功 | weather 卡 1/3 | ttl 120s |
| `capability.list` 成功 | capability 卡 full | ttl 60s |
| `voice.ask` | confirm 问题卡 1/3 | ttl 60s |
| 灰级 MRTR 拦截 | confirm 确认卡 1/3 | token 消费成功即撤,或 60s |

B类车控事件卡规则全量:空调/座椅/方向盘/氛围灯/香氛/大灯/驾驶模式/门舱盖,全部 cardRules 数据,ttl 30s。座椅与门舱盖 builder 只显示非默认项("调了什么显示什么")。

Agent 建卡职责最终收缩为:规则与自动上屏都覆盖不到的纯临场内容(如自由发挥的提醒)。card.show 保留作为逃生舱。
